# VulkanScope 0.41.39 base terminal JSON structure audit


## Immutable predecessor
VulkanScope-0.41.38.zip SHA-256: `0d537fe2f4a3488503f1278eaf13e3c71eed1521db05ffac66efdba6b8a8e4f0`.

## Demonstrated failure
The supplied real-device 0.41.38 log reaches `base report complete checkpoint published before JNI return; terminal marker remains service-owned` and the service immediately reports `Native probe returned after publishing malformed or non-terminal JSON; replacing it with explicit unavailable evidence`. The driver successfully enumerates one Adreno 830v1 physical device and 176 device extensions before that failure. This localizes the defect to final base JSON construction rather than Vulkan enumeration, Turnip loading or service marker ownership.

## Root cause
The final base builder appends the device `surface` object but does not append the closing brace for the enclosing device object before the loop exits and the `devices` array/root are closed. The intermediate `baseReadySnapshot` uses the correct `}}]}` suffix, while the final stream used only the surface closing brace followed by `]}`. The resulting terminal checkpoint is malformed exactly as the post-JNI strict streaming parser reports.

## Repair
0.41.39 closes every device object inside the device loop before closing the devices array/root. It also adds a bounded native container-balance gate that understands quoted strings and escapes and is required both before completeness metadata rewriting and after the final completeness fields are appended. The service-side strict `JsonReader` terminal validation remains intact.

The base collector also removes `vkDestroyInstance` calls from its one-shot dedicated-process path so the implementation matches the existing process-owned teardown requirement rather than risking custom-driver teardown on the publication/JNI-return critical path.

The predecessor fails the per-device closure, native structural-validation and process-owned base-teardown requirements. The same verifier passes against 0.41.39.
