# VulkanScope 3.0.0 Edge-to-edge Chrome and Overlay Coordination Audit

## Immutable predecessor and observed failures
- Immutable predecessor: VulkanScope 2.1.16, 791 files, ZIP SHA-256 `dac7f4e5751aef4f194effa3c5f9c979b168439c610c42adc19bccd2f99fc567`.
- The supplied portrait runtime screenshot is the visual oracle for the remaining chrome geometry: the first page surface begins exactly at the header edge instead of continuing slightly beneath the translucent header.
- Earlier supplied runtime evidence established the required coordinated ordering for the single pager, transient status surfaces and scroll indicators; the same behavior must remain orientation-independent.
- Post-fix device replay is not available in this packaging environment and is not claimed PASS.

## Current Android API research
- Current Android edge-to-edge guidance states that `enableEdgeToEdge()` enables drawing behind system bars on older supported Android releases and that `WindowInsets.navigationBars` describes the live navigation-bar region.
- Current Android guidance also states that disabling navigation-bar contrast enforcement allows the three-button navigation bar to remain fully transparent so application content/protection can draw behind it.
- Interactive content continues to respect navigation-bar insets; the change is limited to the visual backing under the system navigation controls.

## Classified production changes
- `USABILITY/CHROME/SYSTEM-BAR`: enable edge-to-edge consistently, keep navigation-bar contrast enforcement disabled, use a transparent platform navigation-bar color, and draw the same bounded retained-layer glass backing in the live bottom or side navigation-bar inset.
- `USABILITY/HEADER/UNDERLAP`: page content begins 10 dp beneath the translucent header instead of exposing a touching rounded edge exactly at the header boundary. The sticky pager clamp remains at the real header boundary.
- `USABILITY/OPENING`: remove the two decorative endpoint dots from the opening accent rule and extend the rule itself across their former span.
- `REGRESSION/OVERLAY/COORDINATION`: pager-lane reservation begins before the visual glass join, transient status movement and scroll-indicator movement use the same prompt bounded motion timing, and their z-order stays above scrolling search/content surfaces while the pager remains below them.

## Security and performance boundary
- Vulkan/native/JNI collection, Vulkan registry/generated data, report/Database/export semantics, Turnip handling, storage/network permissions, endpoints, ABI targets and dependency versions remain predecessor-equivalent.
- No PixelCopy, bitmap screenshot, `toImageBitmap`, framebuffer readback, per-frame bitmap allocation or unbounded blur path is introduced.
- The system navigation protection reuses the existing retained blurred `GraphicsLayer` and `VulkanGlassTint`; no additional page capture pipeline is added.
