# VulkanScope 0.41.18 Full Correctness and Report Integrity Audit

## Scope
- Canonical Vulkan names and raw unknown fallback behavior.
- Instance, device, layer and layer-extension enumeration state.
- Base checkpoint/crash/timeout report integrity.
- Surface/WSI query-state classification and stale-evidence handling.
- UI, Analysis, TXT, HTML and technicalReport provenance parity.
- Native ownership, bounds, security-sensitive paths, memory/resource cleanup, repeated queries and release usability.

## Correctness changes
- Removed official-looking synthetic unknown Vulkan names and kept unknown values as explicit raw unknown evidence.
- Preserved bounded partial layer and layer-extension enumeration evidence instead of converting query failure to an empty successful list.
- Made `baseReportComplete` authoritative and prohibited partial checkpoint fallback after timeout or native crash.
- Distinguished a zero-length startup crash marker from a signal-written crash marker.
- Made Surface WSI prerequisite absence Not applicable only after complete instance-extension enumeration; uncertainty remains Unavailable.
- Added explicit Surface query status/reason and device-layer/per-layer extension provenance across UI, Analysis snapshots, TXT, HTML and technicalReport.
- Converted metadata/Surface orchestration failure to explicit current-cycle Unavailable evidence instead of retaining stale successful state.
- Removed a duplicate physical-device properties query from the isolated Surface probe.
- Corrected release-verifier ordering so the Image Format Properties2 fixed-query recipe gate executes before the final PASS decision instead of appending an unenforced error afterward.
- Normalized TXT/HTML pre-Android-P version-code deprecation suppression to block-safe Kotlin annotation syntax, removing the ambiguous block-expression annotation warning without changing compatibility behavior.
- Removed three unreachable legacy Compose helpers (`SectionCard`, `KeyValue`, `DataRow`) after reference-count review; active UI paths are unchanged and the release verifier prevents their accidental reintroduction.

## Safety and resource review
- Result-file reads remain bounded to 64 MiB and the Database submission remains independently bounded to the existing complete-payload limit.
- Enumeration counts are bounded and second-stage returned counts are checked against allocated capacity before resize/indexing.
- Android native windows are released after `VkSurfaceKHR` creation and Vulkan Surface/Instance ownership remains explicitly destroyed on normal paths.
- No new manual heap ownership, unbounded retry loop, cleartext network path, background report upload, arbitrary driver path fallback or path traversal behavior was introduced.
- No concrete new RAM/resource leak or privilege/security vulnerability was identified in the reviewed 0.41.17 ownership paths; the fixes are correctness/provenance and fail-closed hardening.

## Compatibility
- Vulkan/query/header baseline: 1.4.360.
- Android compile/target API: 37.
- Submission schema: 2.
- technicalReport schema: 3.
- Release ABIs: arm64-v8a, armeabi-v7a, x86_64.
- VulkanScope Database 0.39.11 remains schema-compatible; no D1 migration is required.

## Specification verification
- Khronos Vulkan Registry was rechecked for this release on 2026-08-27; the current published registry/specification baseline is Vulkan 1.4.360 dated 2026-08-14.
- The checked-in Vulkan-Headers/query baseline remains 1.4.360 and unknown/future values remain raw unknown evidence rather than fabricated registered-looking tokens.

## Release gates
- Source verifier, JSON/XML/Python parsing, exact source manifest, release hygiene, compile-regression/dead-helper scan and Database 0.39.11 Worker contract suite pass.
- Final ZIP is re-extracted and the verifier plus parse/manifest gates are repeated against the extracted archive before publication.
- Full Gradle APK compilation is not claimed in the audit environment because Gradle 9.7.1 distribution resolution stops at `services.gradle.org` DNS (`UnknownHostException`) before Android compilation begins.
