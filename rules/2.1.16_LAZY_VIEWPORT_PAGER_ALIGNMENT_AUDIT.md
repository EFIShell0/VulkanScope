# VulkanScope 2.1.16 Lazy Viewport Pager Alignment Audit

## Immutable predecessor and failing oracle
- Immutable predecessor: VulkanScope 2.1.15, 786 files, ZIP SHA-256 `49c99c11d2045b0ac9197580f3303ec823adbab6db917118d0cd526aa48a895a`.
- Supplied failing oracle: the 2026-09-28 portrait screenshot shows the single pager rendered on top of the `Showing` metric row while the reserved pager slot remains visibly lower.
- The displacement is consistent with the lazy list's non-zero before-content padding being omitted from the page-overlay coordinate. The same coordinate error can occur in landscape because header/system/transient insets change the live before-content padding.
- Post-fix portrait/landscape device replay is not available in this packaging environment and is not claimed PASS.

## Upstream API research
- Android's current `LazyListItemInfo.offset` contract defines an item's main-axis offset relative to the start of the lazy-list container.
- Android's current `LazyListLayoutInfo.viewportStartOffset` contract states that the viewport start can be negative when non-zero before-content padding is applied. Therefore an item offset used by a sibling page overlay must be mapped into viewport coordinates as `itemOffset - viewportStartOffset`; assuming a fixed header/padding amount is not robust.
- The existing `contentPadding` remains content padding rather than a modifier offset on the list, so the conversion belongs at the overlay-coordinate boundary rather than by moving the list or spacer.

## Root cause
- 2.1.15 made one page-level pager follow `LazyListItemInfo.offset` directly. That removed duplicate pager ownership, but it treated the raw lazy-item offset as if it were already the page-overlay viewport Y coordinate.
- With non-zero top `contentPadding`, `viewportStartOffset` can be negative. Applying the raw item offset directly places the overlay above its spacer by the omitted padding magnitude.
- The same omission existed in the previous-item and next-item bridge calculations, so composition-gap recovery could preserve the same misalignment.

## Repair
- Direct pager geometry now uses `direct.offset - layoutInfo.viewportStartOffset`.
- Previous- and next-item bridge geometry apply the identical viewport-start conversion after reconstructing the lazy-list item offset.
- The single overlay pager, retained pager height, spacer, join progress, header clamp, shared backdrop source, blur radius/tint and overlay ordering are otherwise unchanged.
- No orientation-specific correction, hard-coded header height or independent pager animation is added.

## Security, performance and semantics
- No native/JNI/Vulkan, report, Database, export, Turnip, manifest, permission, network, endpoint, ABI, dependency, registry or artwork behavior changes.
- The correction is integer coordinate arithmetic inside an existing derived state and does not add allocations, bitmap capture, framebuffer readback or extra rendering passes.
- Existing bounded retained-layer blur and ordinary crisp page replay remain unchanged.
