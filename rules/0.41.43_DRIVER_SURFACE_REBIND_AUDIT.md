# VulkanScope 0.41.43 driver-bound Surface rebind audit

Immutable predecessor: VulkanScope 0.41.42 ZIP SHA-256 `8ca0dc49c2e4eb015fe18c293c444a9bc826dc8a768f36b7058eb871ba50ee33`.

## Demonstrated failure

A real-device VulkanScope 0.41.42 run preserves correct Surface evidence during ordinary collection, but changing the selected Vulkan driver source can make the next Surface probe Unavailable until the user manually recreates the Surface by toggling Surface state. The 0.41.42 UI keeps one attachment-lifecycle `SurfaceView` across driver mutation and immediately starts the replacement full collection with that pre-mutation Surface identity.

Android API 34+ documents `SURFACE_LIFECYCLE_FOLLOWS_ATTACHMENT` as creating the Surface when the SurfaceView attaches and retaining it until the SurfaceView detaches. The demonstrated manual Surface recreation is therefore treated as the exact regression oracle rather than as driver capability evidence.

Classification: `BUG`, `USABILITY`.

## Successor contract

- Each real driver-mode change and forced same-mode Turnip package activation invalidates the old Surface identity and token before collection.
- Driver mutation advances a Compose-owned Surface host generation. The old `SurfaceView` is detached and a replacement host is created for the new driver generation.
- Surface created/destroyed callbacks carry the host generation. A late callback from an older host cannot become current and cannot clear a newer Surface.
- Driver collection is deferred until the replacement host publishes a live Surface. Driver mutation does not start a full collection against the previous Surface.
- Ordinary Surface recreation without a driver change remains a Surface-only refresh and does not force a full report recollection.
- Existing one-retry `VK_ERROR_NATIVE_WINDOW_IN_USE_KHR` handling, stale-result generation checks, Surface Unavailable semantics, Vulkan query coverage and report schemas remain unchanged.

## Regression evidence

The failing-before-fix oracle is `tools/verify_driver_surface_rebind_04143.py --root <immutable 0.41.42>`, which fails before the fix. `tools/test_driver_surface_rebind_state_machine.py` models driver change, stale old-host create/destroy callbacks, forced same-mode package replacement, ordinary Surface recreation and collection-time Surface deferral. `tools/test_driver_surface_rebind_negative_mutations.py` rejects removal of host recreation, stale-host rejection and driver-change rebind preparation while retaining an unrelated diagnostic-text false-positive control.
