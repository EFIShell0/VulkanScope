## User-observed regression oracle
- The supplied header screenshots show that simple alpha transparency is not sufficient: the top region needs a denser frosted/mosaic translucent treatment while still allowing moving page content to remain perceptible beneath it.
- The supplied file-manager screenshot shows the combined layout/sort popup still spending its upper-left space on a text heading instead of the requested contained red close action.
- The supplied paged-list screenshot shows the sticky page card disappearing after downward scrolling and competing for the same vertical overlay space as transient status surfaces and the top scroll indicator.
- Page changes currently animate the entire pager surface rather than only the displayed page number.

## Classification and patch boundary
- `USABILITY/HEADER`: preserve the edge-to-edge translucent header but add a bounded, deterministic mosaic/frosted overlay and stronger translucent backing without making the header opaque.
- `USABILITY/FILE-MANAGER`: replace the popup heading with a circular VulkanScope-red close action at the upper-left of the shared combined layout/sort popup.
- `BUG/PAGINATION`: retain the sticky pager item index after it leaves `visibleItemsInfo` so the pager cannot fall back behind the app header after it has already been passed.
- `USABILITY/PAGINATION`: remove whole-pager page-change motion. Only the non-editing page number cross-fades; the pager surface, arrows, outline and layout remain stationary when the page changes.
- `USABILITY/OVERLAY-COORDINATION`: animate transient top-overlay clearance and reserve distinct vertical lanes for status surfaces, the top scroll indicator and a pinned pager. The pager translates only when entering/leaving its pinned position or when the live overlay lane height changes.
- Production runtime changes are restricted to `app/src/main/java/com/efishell/vulkanscope/MainActivity.kt`; `app/build.gradle.kts` changes release identity only. Native/JNI, Vulkan 1.4.364 registry/generated data, report/Database/export semantics, manifest, permissions, endpoints, ABI targets, dependency pins and packaged identity artwork remain predecessor-equivalent.
