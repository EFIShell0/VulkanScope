# VulkanScope 0.32.2 build fix

The Android API 37 SDK exposes `Display.hdrCapabilities` as nullable to Kotlin. VulkanScope must not force-dereference this value. When the platform returns no HDR capability object, the report must preserve the unknown/not-exposed state: legacy HDR-type enumeration uses an empty list and desired luminance fields are serialized as `Not exposed`. No HDR support, luminance, or unsupported state may be guessed from a null object.

This release is otherwise behavior- and design-preserving relative to 0.32.1. Material 3 Expressive visual changes remain confined to Info and Settings.
