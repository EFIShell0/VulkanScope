# VulkanScope 0.34.8 CapsViewer 4.13 FormatFeatureFlags2 and expressive icon audit

## Scope
- Database excluded.
- Fix the verified VulkanScope 0.34.7 consumer gap for extended format feature flags announced by VulkanCapsViewer 4.13.
- Refresh Settings and Info icon artwork only; preserve navigation behavior and layout.

## FormatFeatureFlags2 data flow
- Native `format2` continues to query `vkGetPhysicalDeviceFormatProperties2` with `VkFormatProperties3` chained when Vulkan 1.3 or `VK_KHR_format_feature_flags2` is available.
- Native output now carries an explicit `featureFlags2Available` boolean in addition to legacy and 64-bit values.
- Kotlin merge prefers all three `VkFormatProperties3` masks only when that evidence is true and the values parse successfully.
- Legacy 32-bit masks remain the compatibility fallback.
- Parsing uses unsigned 64-bit hexadecimal conversion to preserve the complete bit pattern, and unknown-bit hexadecimal rendering also uses the unsigned representation.
- Vulkan 1.3 availability uses a packed API-version comparison rather than minor-version-only logic.
- Existing `FormatEntry` consumers therefore propagate the selected 64-bit masks to Formats UI, structured report, TXT and HTML without parallel data-model divergence.

## Material 3 Expressive icons
- Settings keeps the same semantic destination but uses rounded slider-style expressive vector geometry.
- Info keeps the same semantic destination but uses rounded outlined information geometry.
- Existing Compose tint, 24 dp sizing, content descriptions, app-bar placement and navigation geometry remain unchanged.

## Non-goals
- No database/schema change.
- No Android-external WSI probing.
- No updater, Obtainium, Turnip/SAF, report gating, surface, HDR or capability scheduling change.
