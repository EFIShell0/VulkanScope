# VulkanScope 1.2.5 Settings destination transition audit

## Triggering evidence
The 1.2.4 Settings root animates the three destination cards only when the root chooser appears. Selecting a destination updates `selectedSection`, after which `SettingsPage` returns the selected destination directly. The selected destination therefore replaces the chooser without a content transition even though the chooser-card entrance itself is animated.

## Correction
Settings destination selection now drives one bounded `AnimatedContent` state keyed by `selectedSection`. The content lambda uses the animated target value. Forward navigation from the chooser uses a short horizontal slide plus fade, Back uses the matching reverse motion, and peer replacement has a bounded fade fallback. The existing staggered chooser-card motion is retained unchanged.

Driver & Update Preferences was extracted into a dedicated composable so all three destination bodies participate in the same content transition without changing driver-management state, query behavior, update preference semantics or storage behavior.

## Evidence boundary
The change is source-verified and state-model tested. Real-device frame pacing, visual rendering, TalkBack/TV focus behavior and Android build execution remain separate evidence classes and are not represented as PASS unless actually executed.
