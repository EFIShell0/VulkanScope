# VulkanScope 0.41.33 Vulkan 1.4.361 CMake registry-lock build fix audit

## Proven regression
Android Studio/Gradle fetched Vulkan-Headers exact commit `31386378257ac8653ce5b32c93baec385259ebbe` / tag `v1.4.361` successfully, then CMake failed with `Vulkan registry baseline mismatch: expected locked Vulkan 1.4.361 vk.xml`. The 0.41.32 build script incorrectly assumed the Vulkan-Headers repository copy of `registry/vk.xml` must be byte-for-byte identical to the separately sourced Vulkan-Docs canonical snapshot.

## Fix
The bundled canonical Vulkan-Docs snapshot remains byte-for-byte locked to SHA-256 `3ff4984b841932e04eebeb4ce2a6613ebd37c00ffb2e96549785b2c5d7da9e1d`. Vulkan-Headers remains pinned to exact commit `31386378257ac8653ce5b32c93baec385259ebbe`. The fetched `vulkan_core.h` must still report `VK_HEADER_VERSION 361`, and the fetched Vulkan-Headers registry must semantically identify header version 361 and contain the Vulkan 1.4.361 `VK_NV_private_data_base_handle` sentinel. The fetched Vulkan-Headers registry is no longer compared to the Vulkan-Docs byte hash.

## Regression prevention
`tools/verify_cmake_registry_lock.py` fails if the old cross-repository byte-hash comparison returns, if the bundled canonical Vulkan-Docs SHA gate is removed, if the exact Vulkan-Headers commit drifts, or if semantic 1.4.361 checks disappear. `tests/golden/0.41.32_regression_contract.json` allows only the evidenced CMake build-chain change among the locked predecessor runtime/build files.

## Scope
No Vulkan runtime query/report coverage, Database schema/technicalReport version, timeout policy, probe memory ceilings, concurrency semantics, security behavior, or UI capability interpretation changes in 0.41.33.

## Executed CMake regression fixture
A local CMake configure fixture pre-populated the Vulkan-Headers source with a header reporting version 361 and a registry carrying the required 1.4.361 semantic markers but an intentionally different byte SHA from the canonical Vulkan-Docs snapshot. Configure succeeded. Changing the fetched header to 360 failed with `Vulkan header baseline mismatch`; changing the fetched registry semantic header version to 360 failed with `Vulkan-Headers registry semantic baseline mismatch`.

The targeted verifier was also negative-tested by restoring the old cross-repository SHA pattern; it failed as required. An unallowlisted AndroidManifest mutation separately failed the 0.41.32→0.41.33 golden regression contract.
