# VulkanScope 0.41.15 canonical enumeration and HDR provenance audit

## Scope
- Canonical Vulkan enum presentation for present modes, color spaces and formats.
- Instance extension/layer enumeration outcome and completeness.
- Physical-device and extension-query applicability semantics.
- Android Display/HDR null-versus-empty provenance.

## Corrections
- Added the current Khronos `VkPresentModeKHR` names for shared-demand refresh, shared-continuous refresh and FIFO latest-ready. Unknown numeric present modes, color spaces and formats now remain explicit raw `UNKNOWN(<value>)` evidence instead of synthetic Vulkan symbols.
- Instance extensions and layers now preserve available, incomplete and unavailable enumeration outcomes with bounded reasons and completion state. Repeated `VK_INCOMPLETE` preserves partial positive entries without claiming completion.
- Failed physical-device enumeration now reports Unavailable with exact VkResult evidence. Successful zero-device enumeration remains Not applicable.
- Extension-group Not applicable requires completed device-extension enumeration; incomplete/unavailable enumeration no longer proves extension absence.
- Android HDR status distinguishes API 24-33 null `HdrCapabilities` as Unknown/not exposed from a non-null empty supported-type list as Unavailable. API 34+ uses current mode supported HDR types.

## Preserved contracts
- Vulkan 1.4.360, Android API 37, schema 2 / technicalReport 3 and three release ABIs are unchanged.
- No GPU/vendor/marketing capability inference is added.
- Database submission remains explicit, complete-report only and fixed-endpoint.
