# VulkanScope 1.0.15 SAF launch-first and full application audit

## Demonstrated runtime bug
VulkanScope 1.0.14 checked `PackageManager.resolveActivity(..., MATCH_DEFAULT_ONLY)` before invoking every system document picker and also forced the check to false on Android TV. A real device can therefore report `SAF unavailable` and take the fallback path even though the registered `OpenDocument`/`CreateDocument` Activity Result launcher can open the system picker. The authoritative Android SAF model is to invoke the system document picker for `ACTION_OPEN_DOCUMENT`; PackageManager query/resolve results can be filtered by package visibility and are not authoritative capability evidence for this system-mediated action.

1.0.15 removes the resolver/TV availability guess. Turnip import, Analysis snapshot import/export, Minimum Profile import/export, raw technicalReport export and complete TXT/HTML export attempt the registered system picker first. Only `ActivityNotFoundException` or `SecurityException` at launch causes the existing bounded fallback. User cancellation after a successful picker launch does not cause fallback.

## Storage and security
The change adds no permission, endpoint or broad-storage path. Turnip fallback remains exact-name bounded to `turnip_01.zip` through `turnip_10.zip`; Analysis fallback remains immediate-file bounded under VulkanScope app-specific exchange roots. `MANAGE_EXTERNAL_STORAGE` is absent. Existing package/file/report size ceilings and canonical-parent checks remain unchanged.

## Specification and generated-data audit
The canonical Khronos Registry was rechecked 2026-09-09: Vulkan 1.4.362, published 2026-09-04. The bundled 1.4.362 registry/header/query baseline therefore remains current. Generated registry/query parity, report semantics and Vulkan Video/Profile gates are re-run rather than changed speculatively.

## Full audit scope
The release gate rechecks manifest/exported components, cleartext/backup policy, update and Database transport constraints, storage traversal, lifecycle/cancellation, native ownership and bounded enumeration, report completeness/loss, generated registry parity, Kotlin/CMake compile guards, accessibility/RTL/TV/large-text behavior and reproducible packaging. No additional production change is accepted without a concrete failing oracle.

## Test-gap repair
The aggregate quality gate had retained 1.0.12 and 1.0.13 release-specific suites but omitted the 1.0.14 compile-fix suite. 1.0.15 restores that suite to the aggregate gate and adds its own launch-first verifier/state-machine/negative-mutation suite. The retained 1.0.12 suite is updated only to recognize the explicit 1.0.15 launch-first supersession while retaining its bounded fallback and icon contracts.

## Evidence boundary
Static/source/model gates do not prove device UI rendering, OEM document-provider behavior, sanitizer/profiler cleanliness or Android assemble/lint/unit unless those are actually executed. Such evidence remains NOT EXECUTED when the environment cannot run it.

## Semantic UI refinement
The supplied Analysis screenshot showed the Database permalink card and Share action reusing the same chain symbol, while the supplied Display screenshots showed HDR capabilities, display modes and Display/Vulkan interpretation all reusing the same undifferentiated monitor badge. 1.0.15 separates those meanings without changing underlying evidence: Share link uses the share glyph, Copy link remains a chain action, Database permalink & QR uses a dedicated QR glyph, HDR sections retain the monitor motif with an HDR badge, display modes use a MODE badge, and Display ↔ Vulkan interpretation overlays the existing Surface glyph on the monitor motif.

The five primary navigation icons now use one finite click-driven animation composable in both the short bottom navigation and the landscape/TV rail. Overview pulses, Vulkan tilts/pulses, Surface lifts, Display performs a short screen-like squash/pulse and Extensions rotates/pulses. Each animation is 320 ms, returns to neutral geometry and has no infinite/background transition or capability-query side effect.

## UI regression evidence
`tools/verify_share_display_navigation_ui_1015.py`, its state machine and its negative-mutation suite cover semantic Share/QR separation, HDR/MODE/Surface monitor badges, both navigation hosts, distinct per-destination motion, bounded duration and QR resource integrity.
