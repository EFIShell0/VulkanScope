# VulkanScope 0.41.9 Image Format Properties2 query-outcome separation audit

## Trigger
A real 0.41.8 report rose from roughly 1476 to 2309 Properties & Limits evidence rows because hundreds of queried `VK_ERROR_FORMAT_NOT_SUPPORTED` tuples were serialized into `detailedProperties`.

## Root cause
0.41.8 correctly preserved exact negative tuple state, but placed negative query outcomes in the same dataset used for Vulkan property/query counts. This preserved semantics at the wrong reporting layer and distorted Properties & Limits totals.

## Correction
0.41.9 keeps successful Image Format Properties2 payloads in `detailedProperties` and moves only non-success tuple outcomes to bounded `imageFormatQueryResults` objects containing canonical tuple name, semantic state and exact numeric `VkResult`. Format detail, TXT, HTML, Analysis snapshots and Database technicalReport consume the separate dataset. Property/query totals do not include it.

## Semantics
`VK_ERROR_FORMAT_NOT_SUPPORTED` is explicit Unsupported evidence for the exact fixed query recipe and tuple. Other non-zero results are Unavailable. Absence means not reported/Unknown only when no result exists. No device-wide or format-wide support claim is inferred from a single tuple.

## Compatibility
Schema 2, technicalReport 3, Vulkan 1.4.360, AGP 9.3.2 and existing security/query-safety rules are unchanged. Historical reports remain readable.


## Final verification
`tools/verify_release.py`, JSON/XML parsing, Python tool syntax and package-hygiene checks pass. The release verifier also proves the checked-in format catalog cannot exceed the companion Database's 4096-entry tuple-outcome bound under the fixed two-tiling / three-variant query recipe. A full Gradle build could not start in the audit environment because Gradle 9.7.0 was not cached and external wrapper download was blocked by DNS; this limitation is recorded rather than reported as a successful APK build.
