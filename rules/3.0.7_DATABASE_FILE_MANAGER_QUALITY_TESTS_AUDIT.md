# VulkanScope 3.0.7 Database, File Manager, Quality and Self-Test UI Audit

## Scope and immutable predecessor

VulkanScope 3.0.7 starts from immutable VulkanScope 3.0.6 (`e2dac49614bad04e8f73d3e92f44f2f2683bd7e65b049f855ad3e2dd5769e070`, 826 files). Production changes are restricted to `MainActivity.kt`; `app/build.gradle.kts` changes release identity only. `AdvancedAnalysis.kt`, `VulkanDependencyGraph.kt`, manifest, native/JNI Vulkan collection, registry/generated assets, report/export schemas, Database transport behavior, permissions, ABI targets and dependency versions remain predecessor-equivalent.

## Visual regression evidence

The supplied Database-list screenshot shows the generic database cylinder glyph at the left of each GPU report card. The requested target is the existing VulkanScope GPU-vendor artwork. The report-list source already carries an explicit `vendor_id`, so the UI can use the established vendor-ID mapping without inferring identity from free-form GPU/model text. Unrecognized IDs continue to use the unknown-vendor asset.

The predecessor file-manager search swaps summary/search content immediately inside both Turnip and shared-storage toolbars. Android Developers Compose animation documentation was rechecked on 2026-09-29. `AnimatedContent`, horizontal expand/shrink transitions and `Modifier.animateContentSize` are documented primitives for bounded content and size transitions. 3.0.7 applies them to both file-manager paths and to file/folder card size changes while leaving file-system validation and storage semantics unchanged.

## Quality calculation audit

The predecessor Quality screen exposes a numeric score and factor strings but does not put the complete formula next to the score. The underlying heuristic starts at 100 and deducts only from explicit collection/safety evidence. 3.0.7 makes that existing basis inspectable and structures every check as title, deduction, trigger and observed evidence. The fixed deductions are 35, 15, 10, 10, 10, 10, 10 and 5 points for the documented conditions; the sum is clamped to a zero-point floor. GPU vendor/model, supported-feature count and benchmark data are not inputs.

The threshold text remains: 95–100 no explicit collection anomalies; 80–94 minor explicit anomalies; 60–79 multiple explicit anomalies; 0–59 severe explicit collection anomalies. These labels describe collection evidence only. The screen explicitly excludes Vulkan conformance, performance ranking, driver certification and vendor/GPU quality claims.

## Active self-test result audit

The native self-test producer is predecessor-equivalent. It returns operational checks for VkDevice creation, a minimal SPIR-V shader module, a minimal pipeline layout and minimal compute-pipeline creation, with exact PASS/FAIL/UNAVAILABLE status and Vulkan detail text. 3.0.7 changes only presentation: target and scope are shown before running; the result adds an overall outcome and PASS/FAIL/UNAVAILABLE/TOTAL counts; each returned test shows its exact status and detail plus a plain-language status meaning. Self-tests remain isolated from canonical capability support and from the Quality calculation.

## Evidence boundary

`tools/verify_release_3007.py` locks release identity, requested UI anchors, the transparent Quality formula, detailed test presentation and protected production hashes. `tools/test_release_3007_state_machine.py` exercises vendor-ID handling, scoring deductions/floor, search open/close state and self-test summary counts. `tools/test_release_3007_negative_mutations.py` requires targeted regressions to fail and documentation-only mutation to remain accepted. `tools/verify_release_3007_regression.py` allowlists only `MainActivity.kt` among production files and requires all protected runtime/spec files to stay byte-equivalent to 3.0.6.

Android compile/assemble and device visual replay are separate evidence classes. They are not marked PASS unless actually executed.
