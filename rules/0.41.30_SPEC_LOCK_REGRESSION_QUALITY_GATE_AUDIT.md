# VulkanScope 0.41.30 spec-lock, regression-contract and quality-gate audit

- Version: 0.41.30 / versionCode 440.
- Predecessor baseline: VulkanScope 0.41.29 ZIP SHA-256 `f1ce1ce0515143f2f2aee32daa9c5f2c613ea16b31b60cc297501c2b1390a1b7`.
- Authoritative published/query baseline: Vulkan 1.4.360 dated 2026-08-14, Vulkan-Docs registry commit `090f1b190d60ced4a1d198fd3747d071cc271b1c`.
- Canonical compile-header baseline: Vulkan-Headers tag `v1.4.360`, commit `0b7f383797fa7be53ae28213e001ae60668ee511`, `VK_HEADER_VERSION 360`.
- The first audit pass found a reproducibility defect: checked-in `registry_query_manifest.json` used schema 6 while `tools/generate_vk_registry.py` still emitted schema 4 and did not reproduce the checked-in catalog manifest.
- The first audit pass also found a gate defect: canonical-header, registry-catalog and field-coverage verifier tools existed but the main release verifier did not execute them, so a normal PASS did not prove real upstream registry/header coverage.
- No Android unit/instrumentation source tree and no CI workflow existed. Existing release verification was primarily static source-anchor/count validation and could not by itself prove predecessor behavior preservation.
- Added `registry/registry_lock.json` so registry and header provenance is commit-pinned rather than inferred from a version label or a floating upstream branch.
- Replaced the stale registry generator with a schema-current reproducible generator that validates locked header version, catalog structs/groups/descriptors, Kotlin validated extension coverage and registry membership. Strict mode derives queryable physical-device Features2/Properties2 extension providers from `vk.xml` and requires exact runtime-extension coverage parity.
- Added manifest provenance fields and physical-device extension coverage list/count. The checked-in metadata now records both authoritative registry and canonical header commits.
- Added `tests/golden/0.41.29_regression_contract.json`. For this tooling-only release it locks 81 production/build-chain files from 0.41.29, normalized `app/build.gradle.kts`, all 104 validated runtime query groups, 301 validated physical-device extensions, 109 implemented physical-device catalog structs and 10 instance dependency candidates.
- Added `tools/verify_regression_contracts.py`. It rejects unexplained production-file changes, build-configuration drift, query/catalog drift, Kotlin/pNext extension mismatch, manifest/snapshot provenance mismatch and CMake/header-lock mismatch.
- Added `tools/verify_upstream_registry.py`. With locked upstream inputs it verifies registry/header membership, exact registry-derived extension coverage, pNext query structure coverage and queried-structure-type report serializer coverage.
- Added `tools/quality_gate.py`. Local mode runs regression contracts plus the complete release verifier. Strict mode additionally validates locked upstream files and regenerates the registry manifest for equality.
- Added GitHub CI quality gates for strict registry/spec verification and Android `lintRelease`, `testReleaseUnitTest` and `assembleRelease`.
- Production Kotlin/C++/resources/manifest/CMake/proguard behavior remains identical to 0.41.29; only application version metadata changed. This is intentional: no new runtime defect was proven during this pass, so unrelated production refactoring was prohibited.
- Local regression contract: PASS, 81 production/build-chain files protected, 104 query groups, 301 validated physical-device extensions and 109 implemented catalog structs.
- Local release verifier: PASS.
- Local quality gate: PASS in local-only mode.
- Negative regression-gate mutations: 3/3 expected FAIL. A production-source byte change, removal of one validated physical-device extension, and registry-lock commit drift were all rejected.
- Strict locked-upstream regeneration could not execute in this container because direct external DNS/network access is unavailable. The official Khronos web registry was independently checked and reports Vulkan 1.4.360 dated 2026-08-14 from registry commit `090f1b190d60ced4a1d198fd3747d071cc271b1c`; the pinned Vulkan-Headers commit is the 1.4.360 update and exposes `VK_HEADER_VERSION 360`.
- `./gradlew --offline :app:assembleRelease --no-daemon` was attempted, but the uncached wrapper tried to reach `services.gradle.org` and failed with `UnknownHostException` before Android/Kotlin/CMake/NDK tasks began. Android release compilation is not claimed as PASS. Lint, unit-test execution, Vulkan Validation Layers and HWASan/real-device profiling were likewise not executable here; CI now carries the build/lint/unit-test gate for a connected repository runner.
