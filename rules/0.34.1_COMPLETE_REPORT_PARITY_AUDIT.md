# VulkanScope 0.34.2 Complete Report Parity Audit

The complete data path was re-audited from native Vulkan collection through DeviceReport, Compose UI, TXT, self-contained HTML, structured technicalReport, Database Worker normalization and VulkanScope Database 0.36.x detail/compare rendering.

The 0.34.0 Host Image Copy layout arrays already enter detailedProperties. Because the Properties UI, TXT DETAILED QUERY RESULTS, HTML Detailed query results and structured Database payload all consume detailedProperties generically, those values propagate without extension-specific presentation code.

Additional parity defects found and fixed in 0.34.2:
- TXT omitted instance-layer extension membership even though HTML and structured reports preserved it.
- TXT/HTML memory, queue and format sections retained raw masks but did not consistently accompany them with the same canonical Vulkan flag names used by the UI/structured Database payload.
- TXT/HTML registry provenance reported the implemented-structure count without exporting the implemented structure-name list.
- The Info UI and HTML report exposed less Android build/security-patch provenance than the TXT diagnostic report.

The Database privacy contract remains deliberately narrower for Android platform metadata. Serial numbers, Android ID, IMEI, MAC addresses, accounts, authentication data and private paths are not submitted.

Current specification check: Vulkan 1.4.360, published 2026-08-14. The pinned query/header baseline remains 1.4.360.
