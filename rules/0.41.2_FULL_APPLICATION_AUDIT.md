# VulkanScope 0.41.2 Full Application Audit

Release target: VulkanScope 0.41.2 / versionCode 412.

## Query-result count semantics

The observed Properties & Limits total of 1473 is valid for the reported device state. The native Vulkan query engine did not gain four synthetic capabilities between 0.40.2 and 0.41.1. The difference from 1469 is the four mandatory `Vulkan Query Safety` evidence rows introduced into the complete detailed-property pipeline by the 0.40.2 audit: queue-family enumeration, memory-heap count, memory-type count, and Surface queue-family enumeration safety. 0.41.2 keeps those rows and labels totals as evidence rows, property/query rows, and safety diagnostics in UI, TXT and HTML.

## Correctness and specification alignment

- Active native checkpoint provenance was corrected from the stale `1.4.357` literal to the published/query baseline `1.4.360`.
- Surface format and present-mode enumeration now use bounded retry-aware helpers with dedicated safety limits, second-stage capacity validation and explicit completion state.
- Partial `VK_INCOMPLETE` results remain positive evidence only; missing values are not converted to unsupported.
- Cooperative-matrix data is not emitted when its second-stage call fails, and a second-stage count larger than the allocation is rejected.
- Sparse image format properties revalidate the second-stage count before indexing.
- Vulkan Video and Vulkan Tool partial enumerations explicitly preserve incompleteness provenance.
- The Vulkan-Headers field-coverage generator now requires header revision 360 with a valid word-boundary expression.

## Security, memory and compatibility

- Turnip installed-bundle resolution is metadata-authoritative: exactly one bounded `meta.json`, schemaVersion 1, one declared Vulkan `.so`, exact private-path containment and a readable non-empty library. The old arbitrary first-`.so` fallback is intentionally superseded.
- Turnip import remains bounded by entry count, per-file size, aggregate size and path length, with canonical extraction containment.
- Turnip import is gated to Android 9+ arm64-v8a plus the existing runtime support state.
- Probe result publication no longer uses `java.nio.file`, which is unavailable below API 26 while VulkanScope supports API 24. It uses an exact bounded UTF-8 output stream, flush/sync and app-private atomic `Os.rename` publication.
- Temporary publication files are deleted after publication failure; isolated Surface ownership and process shutdown behavior remain deterministic.
- No new runtime permission, remote QR endpoint, analytics endpoint, device identifier or automatic report upload was added.

## Reporting and usability

- Surface enumeration completeness is propagated into the Surface capability list and therefore the normal UI, snapshot and technical-report paths.
- Surface format rows are lazy-rendered rather than all being composed inside one list item.
- Properties totals no longer describe safety diagnostics as newly added query properties.
- Canonical submission schema 2 / technicalReport 3 remains unchanged.

## Validation boundary

Static release checks cover source invariants, generated assets, report-path presence, bounded collection patterns, dependency/version pins, manifest policy and package cleanliness. Runtime zero-leak or zero-crash claims require device-side instrumentation such as profiler/ASan/LeakCanary and are not inferred from static review alone.
