- Demonstrated predecessor failures: the driver/update destination is generically labeled `Settings` and ordered first rather than as the requested third nested destination; Check for updates remains visually enabled while a network result is pending even though the controller suppresses duplicate requests.

## Repair scope
- Settings destination order is Info, Reports & Database, Driver & Update Preferences.
- The third destination contains driver management, direct GitHub update preference and Obtainium guidance and is the default Settings destination.
- Update checks own explicit request-lifetime state. Check for updates is disabled only while the request result is pending and is re-enabled immediately when a result arrives or the request is cancelled.
- Result-banner expiry uses a separate cancellable job and checks result identity so an older timer cannot hide a newer result.
- Vulkan collection, registry/query catalog, report serialization, Database transport, driver package validation, update provenance/package validation, permissions, ABIs and dependencies are unchanged.
