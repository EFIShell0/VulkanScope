## Upstream Android recheck
Android Developers guidance was rechecked before editing. Compose text uses natural/content direction and recommends Start/End rather than absolute Left/Right for locale-aware presentation; Compose layout direction is inherited through the UI tree. Android also provides platform/system font families and fallback rather than requiring a bundled application font. The application already declares `android:supportsRtl="true"`.

Primary references checked:
- `https://developer.android.com/develop/ui/compose/text/style-paragraph`
- `https://developer.android.com/develop/ui/compose/layouts/custom`
- `https://developer.android.com/develop/ui/compose/text/fonts`

## Demonstrated 0.80.6 gaps
- Compose's default paragraph direction follows layout direction. Under an Arabic/Hebrew system locale, English/Vulkan technical text could therefore inherit RTL paragraph direction even when the content itself begins with Latin `VK_*`/`Vk*`/`vk*` identifiers.
- 0.80.6 had no explicit release gate proving the application remained on the platform/default font family with no bundled font resource or hard-coded Compose font family.
- The update-available state still used the older green `UPDATE` badge rather than the requested blue information icon aligned with the collection result icon language.

## 0.80.7 correction
- Installs a Material 3 `Typography` derived from the platform/default typography and applies `TextDirection.ContentOrLtr` to every Material text role. Latin/Vulkan technical content stays LTR under RTL layout while actual Arabic/Hebrew content can resolve RTL naturally.
- Keeps relative Start/End layout behavior and does not add bidi control characters to evidence strings.
- Keeps generic Android `sans` theme fallback and ships no app font binaries or Compose `FontFamily` override, preserving OEM/user system font substitution and platform glyph fallback.
- Adds a blue circular `ic_info` status icon to the update-available banner and removes the previous `UPDATE` badge for that state. TalkBack continues to receive the merged polite live-region text rather than a duplicate icon announcement.
