# VulkanScope 1.2.0 UI, reporting and release audit

## Scope

The immutable predecessor is VulkanScope 1.0.19. This release changes presentation and interaction behavior requested for Overview GPU provenance/details, Settings information architecture, watched evidence controls, global All-filter behavior, transient success/failure feedback, scroll indicators, QR presentation, update/Database actions and Surface section iconography. Vulkan query evidence semantics, report schemas and the pinned Vulkan registry/header baseline remain unchanged unless a verified defect requires otherwise.

## GPU identity provenance

GPU device name, vendor ID and device ID remain sourced from `VkPhysicalDeviceProperties` returned by the active Vulkan implementation. The human-readable vendor label is presentation-only mapping of the returned numeric `vendorID`; it is not used to infer Vulkan capabilities. Overview now displays the numeric Vendor ID and exposes the same System-driver details dialog used by Driver manager when current System evidence is available.

## Settings information architecture

Info is presented as a nested Settings section. Reporting and VulkanScope Database controls are a separate nested Settings section. Each section has an icon, explanatory text and the shared expressive navigation-card treatment. The retained Info header action opens the nested Info section rather than a separate standalone information implementation.

## Interaction changes

All filters with an `All` choice now render All as a switch, enabled by default whenever the model selection is All. Specific filters and horizontal arrows are disabled while All is active. Copy/watch/link/Database actions use a bounded transient state: success is a green check, failure is a red X, the action is disabled while feedback is shown, and idle state is restored after 3000 ms. Page scroll arrows use the Vulkan red container with white arrow artwork.

## QR and iconography

The QR code is retained as a normal high-contrast QR image with protected white padding/quiet area and is placed in a structured explanatory card. VkSurfaceKHR uses the existing Surface symbol with a KHR badge. Surface-format search uses the existing Surface symbol with a magnifier badge. HDR/display pages retain shared page scroll indicators.

## Database behavior

Complete-report and validated-network gates remain mandatory. Submission retains `finally` cleanup for in-flight state. A fixed warning explains that a server-side producer-version floor can reject reports from older application releases and that the returned rejection/error text is surfaced to the user. No automatic/background report upload is introduced.

## Specification and security review

The pinned Vulkan baseline remains 1.4.362/header 362. GPU identity is not inferred from Android marketing data. Runtime evidence and registry metadata remain separate. Unknown/unavailable/unsupported states remain distinct. Existing HTTPS origin constraints, payload bounds, complete-report gating, no-truncation policy, ABI set, private driver metadata handling and explicit-user-action upload policy remain in force.

## Validation boundary

`tools/verify_release.py --skip-regression-contracts --skip-nested-verifiers`, `tools/verify_release_1200.py`, the 1.2.0 state-machine test, registry/spec verifiers and package checks are source/static evidence. Android Gradle compile/lint/unit execution is not labeled PASS unless the Gradle 9.7.1 distribution is available to the build environment. Real-device rendering, TalkBack, TV focus, driver switching and network submission remain device/runtime evidence classes and are not converted into source-level PASS claims.
