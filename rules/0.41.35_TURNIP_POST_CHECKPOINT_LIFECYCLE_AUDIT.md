# VulkanScope 0.41.35 Turnip post-checkpoint lifecycle audit

## Evidence

The supplied real-device log shows the dedicated Turnip probe loading `libvulkan_freedreno.so`, enumerating one Adreno 830 physical device, enumerating 176 device extensions, publishing the safe/core checkpoints and finally logging `base report complete checkpoint published before optional metadata`. No later native probe progress appears. This proves the base Vulkan evidence path reached its complete atomic checkpoint and localizes the observed stall after publication.

## Repair

Turnip cleanup is no longer allowed to block result delivery. The custom-driver `VulkanApi` path keeps `vkDestroyInstance` and `vkDestroySurfaceKHR` as no-op cleanup hooks and skips `dlclose`; the dedicated Turnip service process is one-shot and is killed after the native result is published or a fallback result is written. The OS process teardown therefore reclaims the custom driver and Vulkan objects without making the application wait for driver cleanup. The main process also stops/kills the previous probe process immediately after accepting an atomic result.

Timeout handling now rereads the bounded result file and accepts a valid terminal publication before returning an Unavailable timeout. Exhaustive background detail scheduling has a 60000 ms total budget. If the budget is exhausted, every remaining scheduled group is merged through the existing report path as explicit Unavailable evidence and its pending task is completed.

## Regression evidence

`tools/verify_probe_lifecycle_regressions.py --root <0.41.34>` fails for missing one-shot Turnip cleanup, publication termination, timeout recovery and background budget. The same verifier passes on 0.41.35. Negative mutation tests must also prove that removing the custom-driver cleanup bypass, removing timeout recovery or removing the total background budget causes the gate to fail.

## Evidence classes

Local static/spec/regression quality gates are executed for this source release. Android `assembleRelease`, lint/unit tests and repaired behavior on the user’s Turnip device are not executable in this container and are not claimed as PASS.
