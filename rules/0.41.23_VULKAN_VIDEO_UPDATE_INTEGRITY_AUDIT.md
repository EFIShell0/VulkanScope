# VulkanScope 0.41.23 Vulkan Video / update integrity audit

## Scope

This release re-audits Vulkan Video routing and query-state preservation, queue-family partial evidence and direct-update package/version integrity against `PROJECT_RULES.md`. The application remains on Vulkan 1.4.360, Android API 37, submission schema 2 and technicalReport schema 3.

## Vulkan Video routing

`videoCapabilities` is registered as an advanced query. Its native implementation now resides in `collectVulkanAdvancedGroup`; the unreachable device-extension-collector implementation and its special bypass were removed. This keeps descriptor scope, JNI dispatch and native execution aligned.

The bounded Vulkan Video capability recipe reports the exact sampled profile being queried. `VK_SUCCESS` is positive evidence for that sampled profile. Registered Vulkan Video profile-specific errors are retained as Unsupported for the sampled profile only and do not imply codec-wide support absence. Other failures remain Unavailable with the exact numeric `VkResult`.

Required video-extension absence is treated as Not applicable only after complete device-extension enumeration proves absence. Incomplete or unavailable extension enumeration retains Unknown state. Missing video-format query entry points leave explicit Unavailable evidence, and `VK_INCOMPLETE` format enumeration retains bounded partial rows rather than discarding them.
Capability and format entry points are treated independently. A missing `vkGetPhysicalDeviceVideoCapabilitiesKHR` records explicit unavailable capability evidence but does not suppress an otherwise callable video-format query path. Encode sampled-profile capability queries chain the generic encode capability structure together with the required H.264, H.265 or AV1 codec-specific capability structure, and codec-specific fields are emitted only after `VK_SUCCESS`.
Format queries no longer use generic `VK_IMAGE_USAGE_SAMPLED_BIT` as a proxy for video-image support. Decode output/DPB and encode input/DPB are queried independently with their registered Vulkan Video image-usage bits so a non-video image usage cannot distort video-format evidence.

## Queue-family partial evidence

Queue-family video-operation masks obtained for physical devices retained from a bounded incomplete physical-device enumeration remain visible together with explicit Incomplete state. UI, Analysis, TXT, HTML and technicalReport preserve the returned positive mask. Unknown, Unavailable and Not applicable states do not serialize a misleading numeric zero mask.

## Update integrity

The downloaded APK is rejected unless its package identity and signer are valid, its versionCode is newer, and its `versionName` exactly matches the normalized selected GitHub release version. This prevents a different newer package from being accepted merely because it came from the selected release asset path. Existing HTTPS provenance, ABI, size, private-cache and failed-download cleanup requirements remain in force.

## Compatibility

No submission-envelope, schema-2, technicalReport-3, report-hash or D1 migration change is required. Existing complete-report, Surface/WSI, multi-device, Turnip, Database, ownership and package-hygiene rules remain unchanged.
