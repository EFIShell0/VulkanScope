# VulkanScope 3.0.4 Kotlin Compile Restoration Audit

## Scope

VulkanScope 3.0.4 is a compile-regression repair over immutable VulkanScope 3.0.3 (`e81ec55e27168fa576d43bb4ed77b1aabcdde25ea873b20f58bf3322851b53e2`, 811 files). Production runtime-source changes are limited to `MainActivity.kt` and `VulkanDependencyGraph.kt`; `app/build.gradle.kts` changes release identity only. Native/JNI collection, Vulkan registry/generated data, manifest, report/Database/export schemas and endpoints, permissions, ABI targets and dependency versions remain predecessor-equivalent.

## Observed regression

The supplied release build completes C/C++ compilation for arm64-v8a, armeabi-v7a and x86_64, then fails `:app:compileReleaseKotlin`. Six TV-navigation sites read `event.nativeKeyCode`, but the pinned/current Compose key API exposes `nativeKeyCode` on `Key`, reached from a `KeyEvent` through `event.key`. `VulkanDependencyGraph.kt` also explicitly imports `androidx.compose.foundation.layout.weight`; with the pinned Compose Foundation 1.12.0 this resolves to an inaccessible internal symbol, while the public `Modifier.weight` used by the three cards is a `RowScope` member extension.

Official Android Compose API documentation was rechecked on 2026-09-29 before patching: `KeyEvent.key` returns the pressed `Key`, `Key.nativeKeyCode` returns the Android native keycode, and `RowScope.Modifier.weight` is the public row-weight API.

## Repair

The six affected TV-navigation reads now use `event.key.nativeKeyCode`. No key mapping, event-type condition, focus direction, scroll target, delay, Page Up/Page Down behavior or TV-only gate changes. The explicit Foundation layout `weight` import is removed; the existing three `Modifier.weight(1f)` calls remain in their `Row` receiver scope, so graph summary proportions and layout are unchanged.

## Evidence boundary

`tools/verify_release_3004.py` enforces release identity, the corrected key receiver, absence of the invalid weight import, preservation of the three graph weights and retained 3.0.3 behavior anchors. `tools/test_release_3004_negative_mutations.py` reintroduces each compile regression and requires verifier failure while a documentation-only mutation remains accepted. `tools/verify_release_3004_regression.py` requires byte-equivalence with 3.0.3 for every production file outside the two repaired Kotlin files and requires those two files to normalize exactly back to the immutable predecessor using only the documented repairs. Android compilation and runtime replay remain separate evidence classes.
