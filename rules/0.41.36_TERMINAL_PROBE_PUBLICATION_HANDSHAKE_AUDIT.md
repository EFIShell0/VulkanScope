## Demonstrated failure signature

The supplied real-device log is the regression oracle. The Turnip probe reaches `base report complete checkpoint published before optional metadata`, then `VulkanProbeService.onStartCommand$lambda$1` executes `Process.killProcess(Process.myPid())`, the dedicated process receives SIGKILL, and the main process later reports `The dedicated base probe did not complete within the timeout.` before retrying. The same sequence occurs again on the second base attempt. Metadata later proves the shared atomic publication mechanism itself works because the main process accepts an atomic metadata publication.

## Failing-before-fix evidence

This section records the required `failing-before-fix` evidence class.

`tools/verify_probe_publication_handshake.py --root <0.41.35>` is expected to FAIL. It rejects the predecessor for the pre-handoff self-SIGKILL, absence of a terminal sidecar handshake, lack of terminal forced reread, malformed base-ready checkpoint closure, unconditional publication-success logging and duplicate terminal `baseReportComplete` construction.

`tools/test_probe_publication_state_machine.py` is the behavioral/state-machine contract. It tests a previously observed result fingerprint followed by a terminal marker, malformed-terminal fast-fail, explicit unavailable terminal acceptance and an unrelated-marker false-positive control. The behavioral contract is mandatory and is not replaced by source-pattern checks.

## Minimal repair

Production changes are limited to `app/src/main/cpp/vulkanscope.cpp`, `app/src/main/java/com/efishell/vulkanscope/MainActivity.kt` and `app/src/main/java/com/efishell/vulkanscope/VulkanProbeService.kt`.

The service no longer self-SIGKILLs before consumer handoff. It accepts a canonically confined `result.json.done` sidecar path and atomically publishes that terminal marker only after a final native or fallback result has been published. The main process watches the exact sidecar and forces a fresh bounded read of the result even when inode, mtime and length are unchanged from an earlier checkpoint. Missing, oversized, malformed or non-terminal terminal results fail closed immediately instead of consuming the normal timeout. Accepted-result process termination remains main-process owned.

Native base-ready checkpoint JSON is closed structurally. Final base JSON rewrites the single existing `baseReportComplete` field instead of appending a second root key. Final and base-ready checkpoint logs are conditioned on the Boolean atomic publication result.

## Negative mutation and false-positive evidence

The release gate must FAIL when `Process.killProcess(Process.myPid())` is restored in the service, when terminal forced reread is removed, when canonical single-key terminal JSON construction is broken, or when an unallowlisted production file changes. The state-machine test separately proves that an unrelated `.done` file does not trigger acceptance, preventing a gate that passes only by overbroad marker detection.
