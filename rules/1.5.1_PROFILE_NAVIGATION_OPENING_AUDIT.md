# VulkanScope 1.5.1 profile, navigation and opening audit

## Immutable predecessor and classification
- Immutable predecessor: `VulkanScope-1.5.0.zip`.
- Predecessor SHA-256: `484e25750efa956be5ee7ff1d2ebda7acd6e6d31049d4c49c27f8e1aac0c09f9`.
- Predecessor archive census: 697 entries.
- Classification: `USER-DIRECTED/USABILITY` + `CORRECTNESS/REPORTING` + `TEST-GAP`.
- Two supplied runtime recordings were inspected before editing. The current floating bar measured approximately 354 captured pixels across while the supplied reference measured approximately 335 captured pixels across on comparable portrait frames. Their visual heights were already close, while the current bar sat materially farther above the platform navigation controls. The repair therefore reduces maximum width, retains the compact 54 dp height, removes the duplicate Scaffold safe-drawing inset and uses a 4 dp visual gap inside the already system-bounded app window.

## Profiles evidence accounting
- Every mapped capability check now records one of `met`, `verified unmet` or `unknown` from the same extension, struct-qualified feature, property/limit and format evidence path already used by the evaluator.
- Inherited-profile and alternative-group conditions have an explicit tally category. A satisfied alternative group selects one satisfying evidence branch and records the logical group as met, so failed checks from an unnecessary alternative do not produce a contradictory unmet count on a satisfied group.
- When device evidence is unavailable, mapped direct checks and logical groups remain counted as unknown rather than becoming unsupported or disappearing from the tally.
- Catalog-only definitions remain zero-check UNKNOWN entries. Coverage-limited mappings retain their existing UNKNOWN behavior even when all mapped checks are met. Minimum API version remains a separate prerequisite and is not used as profile-support evidence.
- The Profiles page now shows visible aggregate mapped/met/unmet/unknown counts, per-profile mapped/met/unmet/unknown metrics and category rows for extensions, features, properties/limits, formats and inherited profiles. Existing exact missing/unknown evidence remains visible.
- JSON/TXT/HTML profile details retain prior evidence and add the same mapped tally and category breakdown.

## Navigation and opening repair
- Primary navigation remains four destinations and uses the same horizontal bar in portrait and landscape.
- Geometry is capped at 310 dp wide by 54 dp high. Each selected capsule is 42 dp high with 8 dp horizontal inset, 20 dp icons, persistent labels and a 4 dp bottom gap.
- The Scaffold content inset is explicitly zeroed because the app window is already system-bounded. The navigation surface therefore does not receive a second safe-drawing bottom inset.
- Selection feedback is local to its tab cell. The default rectangular indication is disabled, the selected background is clipped to a full capsule and only bounded alpha/scale motion is used. No indicator translates through other cells or stretches outside its own cell.
- Scroll-content clearance is coupled to the 4 dp gap + 54 dp bar + 10 dp content spacing contract.
- The opening sequence now uses a full-screen dark gradient, two bounded radial accent layers, restrained logo settle, a thin center-expanding accent line and a bounded fade/scale exit. Its staged delay sequence is 520 + 500 + 300 + 280 ms = 1600 ms, below the existing 2100 ms startup-gate fallback.
- The predecessor 900 ms splash-handoff watchdog and further 2100 ms gate fallback remain unchanged.
