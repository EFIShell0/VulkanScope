## Vulkan 1.4.364 delta and query correctness

- The registered Vulkan extension census is 477.
- The validated Android-applicable physical-device provider census is 305: 300 stable plus 5 explicitly tracked provisional providers.
- Relative to the predecessor lock, the new query-bearing provider is `VK_INTEL_device_info`.
- VulkanScope extension-gates `VkPhysicalDeviceInfoPropertiesINTEL` in the physical-device pNext chain and serializes all three returned fields: `deviceIpVersionArch`, `deviceIpVersionRelease`, and `deviceIpVersionRevision`.
- A zero triplet is retained as returned evidence; it is not converted into a fabricated graphics-IP version.
- Loader API version, selected physical-device API version, driver version, current published registry/header revision and collector baseline remain distinct report concepts.
- Runtime extension absence is not rewritten as an Unsupported capability claim, and failed/unavailable queries remain distinct from a demonstrated unsupported state.
- Vulkan surface color-space evidence remains distinct from physical Android display gamut/HDR evidence.

## Googlebook OS and desktop Android evidence

- Current Google first-party material names the released platform Googlebook / Googlebook OS and describes it as built on the Android technology stack with desktop foundations from ChromeOS.
- The pre-release Aluminium naming is not used as a runtime identity heuristic.
- No documented public Android API was found that authoritatively identifies a device as Googlebook or exposes a separate Googlebook OS product-version string to ordinary apps.
- VulkanScope therefore does not infer Googlebook from `Build.MODEL`, brand, manufacturer, product, device, hardware, fingerprint or similar strings.
- Public environment evidence is limited to `PackageManager.FEATURE_PC`, `PackageManager.FEATURE_FREEFORM_WINDOW_MANAGEMENT`, ordinary Android build/platform fields and the existing ChromeOS ARC `org.chromium.arc` feature.
- `android.hardware.type.pc` is declared with `required="false"`; it advertises desktop/PC awareness without excluding ordinary Android phones/tablets.
- Googlebook identity/version is explicitly reported as unavailable when the public API does not expose it; PC/freeform state is labelled only as environment evidence.
- The same PC/freeform/Googlebook evidence is present in visible UI, Database JSON, complete TXT and complete HTML reports.

## Adaptive Material 3 navigation and desktop usability

- Compact portrait windows keep the Material 3 Expressive `ShortNavigationBar` destinations.
- Landscape, television and windows at least 600 dp wide use the Material 3 `NavigationRail` path.
- The 600 dp decision uses the current app-window configuration, so freeform Googlebook/desktop window resizing can switch navigation without relying on product identity or physical-display guessing.
- The rail remains vertically scrollable and focus-grouped, keeps a 64 dp minimum item height, expands for large text and allows two-line labels in the large-text path.
- Existing adaptive landscape dialogs and the VulkanScope SplashScreen animation remain unchanged.

## Security and privacy audit

- No new network endpoint was added for Googlebook or registry data; registry inputs remain build-time locked data.
- Database origin/path validation remains fixed to the official HTTPS endpoint, redirects remain disabled on the Database client, and update discovery remains on the established GitHub release path.
- No WebView, custom permissive `HostnameVerifier`, custom trust-all `X509TrustManager`, process execution path, world-readable/world-writable Android mode, cleartext-traffic enablement or new sensitive permission was found in the production app source.
- Only the launcher Activity is exported; `VulkanProbeService` remains non-exported.
- `android:allowBackup="false"` and `android:usesCleartextTraffic="false"` remain required.
- Native hardening retains stack protector and RELRO/NOW linker flags; release minification and resource shrinking remain enabled.
- Report submission remains explicit user action; no Googlebook fingerprinting or new identifier collection was introduced.

## Performance, memory and crash-resilience audit

- Googlebook/desktop checks are bounded `PackageManager.hasSystemFeature` lookups and do not trigger native Vulkan collection.
- The 1.4.364 change adds one extension-gated returned-properties structure and no polling or unbounded enumeration.
- Existing bounded archive/probe/report limits, strict streaming probe JSON validation, cancellation, timeout, terminal ownership and publication-generation contracts remain required and are covered by retained gates.
- No recomposition-driven Vulkan query was introduced by the desktop-navigation change.

## Dependency and platform currentity review

- Android compile/target API remains 37 and NDK remains 29.0.14206865 per the project contract.
- AndroidX Core 1.19.1, Compose UI/Foundation/Animation 1.12.1 and Material 3 1.5.0-alpha29 were observed as newer upstream releases during this audit. They are not silently substituted into 1.4.5 because the current project hardening contract pins the validated dependency set and the packaging environment cannot complete an Android compile after a dependency migration.
- Material 3 alpha29 also carries source-level API changes. A dependency-version change without an executable Android build would weaken rather than strengthen release evidence.
- This release therefore changes dependencies only when required by demonstrated correctness/security evidence; no such dependency-specific defect was established by the 1.4.5 audit.
