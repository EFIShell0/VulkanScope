# VulkanScope 3.0.9 Database Time, Driver Identity and Semantic Icon Audit

## Scope and immutable predecessor

VulkanScope 3.0.9 starts from immutable VulkanScope 3.0.8 (`8a6db5123add8f261edfd1aad0a15f528a300dd562f9ce2b3540c84fc493e347`, 836 files). Production runtime changes are restricted to `MainActivity.kt`; `app/build.gradle.kts` changes release identity only. `PROJECT_RULES.md`, this audit, changelog and targeted verification tools are evidence/documentation changes. Native/JNI Vulkan collection, registry/generated data, report/export schemas, Database routes/request bounds, manifest, permissions, ABI targets and dependencies remain predecessor-equivalent.

## Database presentation

The public report list no longer exposes the raw ISO-8601 server timestamp as the primary visual value. The exact server instant is parsed without modification and rendered using Android's device-local medium date format and user-selected time format. The local time-zone label remains visible. Parsing failure falls back to the original bounded server string, so presentation failure never fabricates a date.

Driver-mode styling reuses the exact Overview distinction rather than creating a new palette. Any driver-mode value containing Turnip uses `VulkanAccentSoft`; System and other report values use `VulkanTextPrimary`. The value remains bold in either state. The underlying `driver_mode` payload is displayed as received and is not derived from GPU name, vendor ID or manufacturer text.

## Semantic icon uniqueness

The permanent engineering rules now require one visible icon treatment per semantic role within the same destination/tab/dialog/action group. Reusing a semantic root is permitted only when the visible treatment is differentiated by a meaningful internal or lower-right badge/overlay. Arbitrary decoration is forbidden.

The requested Analysis/Encyclopedia families use explicit variants: Encyclopedia book/reference, book+search and book+question; Requirements registry+search and registry+check; Minimums profile identity, profile+add, profile+save and profile+check; Graph graph+search, graph+summary-grid and graph+compass; Quality shield+check, shield+evidence and shield+question; Tests flask+RUN, self-test+SUM and flask+question. No two requested section headings resolve to the same visible treatment.

## Evidence boundary

`tools/verify_release_3009.py` locks the version, Database time/driver presentation and requested semantic icon variants. `tools/test_release_3009_state_machine.py` covers timestamp fallback/localization semantics, driver-style classification and icon-role uniqueness. `tools/test_release_3009_negative_mutations.py` rejects raw timestamp restoration, loss of Turnip/System styling distinction and duplicate semantic icon treatments while retaining a documentation-only false-positive control. `tools/verify_release_3009_regression.py` restricts production drift to `MainActivity.kt` and release identity.

Android `assembleRelease` and real-device visual/time-zone replay are independent evidence classes and remain `NOT EXECUTED` unless actually run successfully.
