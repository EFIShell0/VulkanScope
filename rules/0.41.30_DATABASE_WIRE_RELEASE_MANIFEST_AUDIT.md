# VulkanScope 0.41.30 Database wire, report identity and release-manifest audit

- Version: 0.41.30 / versionCode 440.
- Published/query and pinned compile-header baseline: Vulkan 1.4.360 dated 2026-08-14, Vulkan-Headers commit `0b7f383797fa7be53ae28213e001ae60668ee511`.
- Found that 0.41.29 added summary scope/count and split loader/instance fields directly to strict schema-2 `gpu`, `driver` and `vulkan` objects. VulkanScope Database rejects additional keys in those exact compatibility envelopes, so an otherwise complete 0.41.29 submission failed before evidence validation.
- Restored the exact schema-2 key sets. Multi-device legacy-summary scope/count and the separated loader/base-instance values remain losslessly available in the additive schema-3 technicalReport.
- Found that the TXT multi-device summary replaced the exact `GPU: <first device>` identity line with a device count and replaced `Loader / instance API` with split labels. The Database validates those identity lines against the envelope. Restored both compatibility lines and added explicit summary-scope/count plus split loader/base-instance lines so neither compatibility nor semantic precision is lost.
- Corrected offline HTML Available badges from Vulkan-brand red to blue while retaining green Supported, red Unsupported, amber Unavailable/Not applicable and gray Unknown states.
- Found that release verification treated the entire development checkout as the source package. Historical tracked material, ignored native/Gradle outputs and Python cache files outside the explicit delivery list therefore caused false package failures. Verification now validates and scans the exact `files.txt` delivery universe, including normalized path, confinement, uniqueness, regular-file and symlink defenses.
- Re-reviewed report/export preservation, collection serialization, stale-generation suppression, updater and fixed Database network paths, Turnip package confinement/read-only lifecycle, isolated-probe cleanup, JNI/native ownership and bounded allocation. No additional concrete source-level security or ownership defect was identified in those paths. Runtime leak absence is not claimed without real-device profiler evidence.
- Submission schema remains 2, technicalReport remains 3, the fixed HTTPS endpoint is unchanged, and VulkanScope Database 0.39.12 requires no storage migration or hash rewrite for this producer correction.
