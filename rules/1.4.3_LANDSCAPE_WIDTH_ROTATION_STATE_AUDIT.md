## Observed failures

### USABILITY — landscape filter width

The supplied landscape screenshot shows the closed single-filter selector spanning the available content width while the expanded options surface stops at the inherited 560 dp cap. The 1.4.2 source confirms `dropdownWidth = maxWidth.coerceAtMost(560.dp)` despite a full-width selector.

### REGRESSION / PERFORMANCE — rotation restarts collection

MainActivity does not declare orientation/screen-size configuration handling. Android therefore may recreate it on portrait-landscape changes. VulkanScope keeps `latestReport`, collection orchestration and current Surface ownership in Activity fields, so recreation resets the report to null. The replacement Surface then follows the fresh-start branch and invokes the complete collection path. The primary destination also uses plain `remember`, so recreation returns navigation to Overview.

## Upstream verification

Android's current configuration-change documentation states that configuration changes recreate an Activity by default, while configuration types declared in `android:configChanges` are delivered to the existing Activity through `onConfigurationChanged`. The same documentation states that Compose observes configuration values through `LocalConfiguration` and recomposes for the new configuration when Activity recreation is disabled for those values.

The Android adaptive/multi-window guidance identifies `orientation`, `screenSize`, `smallestScreenSize` and `screenLayout` as the relevant size/orientation configuration set for retaining an Activity during window changes. VulkanScope also retains `keyboardHidden` for the conventional orientation configuration contract.

## Repair

- Landscape single-filter expanded width now equals the available selector width.
- Portrait retains the existing 560 dp cap.
- MainActivity handles `orientation|screenSize|smallestScreenSize|screenLayout|keyboardHidden` without Activity recreation.
- Primary destination and physical-device selection use saveable small metadata state.
- Settings subsection and Encyclopedia seed keep their existing saveable state.
- Existing report/collector state stays in the live Activity instead of being serialized into the saved-state Bundle.
- Existing Surface lifecycle behavior remains unchanged: a replacement Surface with an existing report performs only `requestSurfaceRefresh`; a fresh launch with no report performs the full collection.
- `screenshots` remains excluded from source packages.
