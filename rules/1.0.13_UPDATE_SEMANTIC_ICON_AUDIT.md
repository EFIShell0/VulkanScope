## Requested usability defects
The supplied 1.0.12 real-device UI feedback identifies four presentation issues: the supplied Android-head artwork remains visually detached from the Vulkan red icon system, the update-available banner still uses a generic information treatment and an uncontained Review text action, the update confirmation dialog lacks a semantic update glyph and icon-bearing positive action, and Database fetch/submit/browse/compare/link surfaces reuse database iconography too broadly.

These are `USABILITY` defects. The update confirmation's explicit network-disabled positive action is also a retained `CORRECTNESS` boundary because no UI styling change may weaken the existing validated-network/download-confirmation contract.

## Upstream boundary
The canonical Khronos Vulkan Registry was rechecked on 2026-09-09 and still reports Vulkan 1.4.362 dated 2026-09-04. No Vulkan registry/header/query/native/report/schema change is required for this release.

## Production repair
- The exact Android-head path geometry from the supplied artwork remains packaged, while its body/detail colors use VulkanScope `#E2676A` and `#351719`. The two-tone artwork is still rendered through `Image`, so a generic tint does not flatten its detail.
- Update available uses `ic_update_available`; Review uses the common contained right-chevron affordance shared with Details.
- Update confirmation uses the semantic update-available title glyph. Cancel remains the shared X text action. The positive action is a contained `Download update` button with the download glyph and the existing validated-network enablement gate.
- Database fetch, submit and browse actions use separate database-download, database-upload and database-browse glyphs. Database comparison cards use compare; Database permalink/QR uses link; the generic database glyph remains the section identity where appropriate.
- Four new local vector drawables are introduced: `ic_update_available.xml`, `ic_database_fetch.xml`, `ic_database_submit.xml` and `ic_database_browse.xml`.

No update endpoint, GitHub provenance check, APK signature/package/version validation, Database endpoint, payload, report evidence, native Vulkan behavior, SAF/no-SAF routing or permission changes are introduced.
