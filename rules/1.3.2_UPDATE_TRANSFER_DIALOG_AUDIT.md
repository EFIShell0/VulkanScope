# VulkanScope 1.3.2 update transfer dialog audit

## Triggering request
The user requested that APK downloading stop behaving like a transient follow-up after the update confirmation. After pressing Download update, the existing update flow must become a transfer-status surface showing live connection state, transfer speed and a scrollable terminal-style log. The user also requested Pause, Resume and Cancel controls, cancel confirmation after pausing, explicit terminal canceled/downloaded states, and a separate Install action after verification.

## Defect classification
- `USABILITY`: download progress was represented only by the generic status banner and the confirmation flow disappeared as soon as download began.
- `USABILITY/CORRECTNESS`: there was no user-visible pause/resume/cancel state machine or cancel confirmation.
- `USABILITY/CORRECTNESS`: successful APK validation immediately opened Android's installer instead of retaining a verified-download state with a separate explicit Install decision.
- `TEST-GAP`: the predecessor had no targeted behavioral gate covering pause/resume/cancel-confirmation transitions, terminal-state action availability, bounded live-log behavior or the separation between verified download and installer launch.

## Successor behavior
1.3.2 retains the existing explicit update confirmation and replaces the post-confirmation behavior with a transfer state machine: CONNECTING, DOWNLOADING, PAUSED, VERIFYING, COMPLETED, CANCELED and FAILED. The transfer surface reports connection state, speed and downloaded progress and keeps at most 120 live-log entries rendered in monospace.

Pause is cooperative and does not destroy the validated release selection. Requesting Cancel pauses first and opens the established question-glyph confirmation. Resume is uncontained and iconless; the destructive confirmation is contained and uses the X glyph. A confirmed cancel cancels the active OkHttp call, removes partial transfer state and records the cancellation before exposing a terminal Close action.

After package verification succeeds, 1.3.2 intentionally does not call Android's installer automatically. The transfer surface changes to `Update downloaded` with the check glyph and retains the verified private-cache APK. Install is a second explicit action and continues through the existing package-install permission/FileProvider flow. Close explicitly dismisses the terminal surface and deletes the retained cache APK when installation was not selected.

## Retained security and resource boundaries
The official `https://github.com/EFIShell0/VulkanScope/releases/download/` asset provenance check remains unchanged. The 256 MiB body ceiling, private `cacheDir/updates` destination, canonical target confinement, `.part` cleanup, fsync, package parse, package-name verification, signer-lineage verification and strictly newer versionCode/versionName checks remain mandatory. No new permission, endpoint, background updater, storage root, native query, report field or Database behavior is introduced.

## Evidence boundary
Per the user's request, this pass runs only the targeted 1.3.2 verifier/state-machine/negative-mutation/regression/package gates plus the directly retained update-affordance security gate. Android assemble/lint/unit and real-device network/installer reproduction remain separate evidence classes and are `NOT EXECUTED` unless explicitly run.
