# VulkanScope 2.1.1 collection-pager Kotlin compile-fix audit

## Scope
- Release identity: VulkanScope 2.1.1, versionCode 2101.
- Immutable predecessor: VulkanScope 2.1.0 ZIP SHA-256 `56052c138b0369acfea575cda5765e5445bdd3cc7207d0d0c38eb003ffcde9d4`, 706 files.
- Defect category: `REGRESSION` introduced by the 2.1.0 presentation-only 50-item pagination work.
- Production repair is limited to the four `CollectionPager` call sites in `MainActivity.kt` and release identity in `app/build.gradle.kts`.

## Observed failure oracle
The user-provided `:app:assembleRelease` log reached `:app:compileReleaseKotlin` after successful native builds for arm64-v8a, armeabi-v7a and x86_64, then failed at four pagination call sites. The repeated compiler diagnostics were:
- `No value passed for parameter 'onPageChange'.`
- `Argument type mismatch: actual type is '() -> Unit', but 'Int' was expected.`
- `Unresolved reference 'it'.`

The failing predecessor call shape was `CollectionPager(..., page) { page = it }`. `CollectionPager` declares `onPageChange` before a defaulted trailing `pageSize: Int` parameter, so a trailing lambda is associated with the last parameter position rather than satisfying `onPageChange`.

The libadrenotools messages earlier in the same log are compiler warnings and are not the Kotlin compile failure addressed by this release.

A standalone Kotlin compiler oracle using the same parameter ordering reproduces the old form with exit 1 and the same missing `onPageChange`, lambda-to-`Int`, and unresolved `it` diagnostics; the explicit named-argument repair compiles with exit 0. This supplements, but does not replace, the Android application compile evidence class.

## Repair contract
- Every production `CollectionPager` invocation explicitly names `totalItems`, `currentPage` and `onPageChange` inside the argument list.
- The four affected pages remain Features, Formats, Properties & Limits and Extensions.
- `pageSize` retains the default `COLLECTION_PAGE_SIZE` value of 50.
- Search/filter reset and clamping behavior remains unchanged.
- Pagination remains presentation-only and must not truncate report generation, export, Database submission, analysis, profile evaluation or native collection.
- The translucent header, soft scroll intersections, six File Manager layouts, determinate update transfer and Database report-result actions from 2.1.0 remain unchanged.

## Regression boundaries
- Vulkan/native/JNI collection, six-lane scheduler and one-query-per-process isolation are unchanged.
- Vulkan 1.4.364 registry/generated data are unchanged.
- AndroidManifest, permissions, network policy, endpoints, report schemas/content, Database payload/privacy, ABI set and build-chain versions are unchanged.
- The 2.0.6 Surface/TV behavior and all 2.1.0 UI/data contracts remain required.

## Evidence requirements
- `tools/verify_release_2101.py` rejects any production `CollectionPager` call that reintroduces the trailing-lambda binding defect and verifies the retained 2.1.0 contracts.
- `tools/test_release_2101_state_machine.py` exercises 50-item page boundaries and callback-driven page transitions.
- `tools/test_release_2101_negative_mutations.py` must prove the original failing call shape is rejected, must reject representative regressions in the retained 2.1.0 features, and must include a false-positive control for an unrelated non-production change.
- Android compile/assemble, device/runtime behavior and package reproducibility are separate evidence classes. A build not executed successfully is never reported as PASS.
