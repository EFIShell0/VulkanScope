# VulkanScope 0.41.20 full report / registry / stale-state audit

## Scope
The 0.41.19 tree was re-audited end to end under `PROJECT_RULES.md` for fabricated Vulkan naming, incorrect or missing reporting, stale/lost report state, current Vulkan/Android build baselines, incomplete detail, non-standard presentation, security, native/JNI ownership, memory/resource lifetime, performance bounds and usability.

## Correctness fixes
- Preserved the base-probe `instanceApiVersion` separately from the Vulkan loader version and exposed it in Overview, Vulkan, Analysis and schema-3 technical evidence while retaining the existing compatibility field.
- Preserved native physical-device-group `groupProperties` in the Kotlin merge path instead of silently dropping them. Bounded `VK_INCOMPLETE` results retain the partial group payload, exact numeric `VkResult`, explicit status/reason and `groupEnumerationComplete=false` through UI, Analysis, TXT, HTML and schema-3 technical evidence.
- Removed the synthetic per-device “group containing device” placeholder; device-group membership is now represented only by the actual returned instance-level group properties.
- Preserved Surface-probe instance API, the exact Surface-format query function selected, returned format count and canonical VkResult text.
- Added explicit schema-3 `querySafety` booleans and canonical Surface VkResult strings while retaining the raw numeric Surface results; TXT/HTML also identify `baseReportComplete` explicitly.
- Prevented ad-hoc/lazy query work from racing the still-running full collection and then being overwritten by a later enrichment snapshot.
- Surface changes received during full collection now request a fresh current-state collection after pending work drains instead of being discarded.
- Driver-mode changes always request a new Vulkan collection, including when no live Android Surface exists, so report evidence cannot remain attributed to the previous driver. Collection, Surface and ad-hoc probes snapshot the active mode; switching mode clears the old report and suppresses publication of older-mode in-flight results.
- Lazy/background-query exceptions and blank native results now produce explicit Unavailable query evidence through the normal merge path.
- Profile extension scope certainty now uses instance-extension completion for instance-scoped requirements and device-extension completion for device-scoped requirements.
- Android 16 r.7 directly mandated features and safely comparable integer/boolean properties were added to the lightweight evaluator. Full profile coverage remains intentionally UNKNOWN unless a verified failure is found because inherited profiles, alternate capabilities, formats and other official requirement classes are not fully implemented by the lightweight evaluator.

## Canonical naming and registry-reference fixes
- Known physical-device types now use exact `VK_PHYSICAL_DEVICE_TYPE_*` enum names; unknown future numeric values use a raw `UNKNOWN(raw=...)` form that cannot be mistaken for a registered Vulkan token.
- Replaced Vulkan 1.x minor-only API gates with major+minor comparisons so a future higher major Vulkan API cannot be misreported as older than Vulkan 1.1/1.4.
- The checked-in extension reference is now presented explicitly as a supplementary subset, never as a complete registry census.
- Blank embedded registry fields are displayed as Unavailable instead of being interpreted as absence.
- The duplicate hand-maintained known-extension set was removed; the explorer subset derives directly from the checked-in reference map and includes the Vulkan 1.4.358/1.4.359 additions already present in that asset.
- Stale generated audit metadata was synchronized to the native catalog: 109 implemented physical-device structs, 104 validated runtime query groups and 268 runtime registry-token references. The misleading `runtimeExtensionTokens` audit-list field was removed and the canonical count field is `runtimeRegistryTokenReferenceCount`; the old count name remains only as a backward-compatibility technicalReport/read alias.

## Security / resource review
- Manifest remains cleartext-disabled and backup-disabled; FileProvider and the isolated Vulkan probe service remain non-exported, with only the launcher Activity exported.
- Update handling retains fixed release provenance, bounded response/download sizes, private cache storage, package identity, signing-lineage/set checks, monotonic version checks and invalid-file cleanup.
- Database submission remains explicit, fixed-origin HTTPS, no-redirect, complete-report-only and bounded/all-or-nothing.
- Turnip import retains entry/path-length, entry-count, per-file and aggregate expanded-size bounds, canonical path confinement, exact single metadata/library selection and private-storage installation.
- The libadrenotools FetchContent pin was corrected from a short commit plus `GIT_SHALLOW TRUE` to full commit `8fae8ce254dfc1344527e05301e43f37dea2df80` with `GIT_SHALLOW FALSE`; this preserves the same source revision while complying with CMake commit-hash fetch semantics and improves dependency traceability.
- JNI UTF string acquisition/release pairs, Android native-window acquisition/release paths and reviewed Vulkan instance/device/surface/shader/pipeline ownership paths remain paired. Static source review found no new concrete resource leak, but runtime driver/device leak freedom requires real-device profiling and is not claimed here.

## Performance / usability
- Vulkan probes remain isolated, serialized and bounded. Large evidence remains lazy/searchable rather than silently truncated.
- Extension explorer copy now distinguishes runtime enumeration from the checked-in reference subset and avoids false negative metadata wording.
- Current collection state gates potentially stale ad-hoc work instead of allowing duplicate native probes that can later be overwritten.

## Baseline
- Khronos published Vulkan registry/specification baseline rechecked for this audit: Vulkan 1.4.360, 2026-08-14.
- Vulkan-Headers pin remains commit `0b7f383797fa7be53ae28213e001ae60668ee511`, corresponding to 1.4.360.
- Android compile/target API remains 37; AGP 9.3.2 and Gradle 9.7.1 remain compatible with the project baseline.
- Submission schema remains 2; technicalReport schema remains 3; required ABIs remain arm64-v8a, armeabi-v7a and x86_64.

## Build-verification boundary
Static source/package verification is not a substitute for an APK build, instrumented device tests, validation-layer runs, ASan/HWASan or LeakCanary/profiler testing. Any unavailable build/runtime validation must be reported as unavailable rather than as PASS.
