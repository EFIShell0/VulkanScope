## Demonstrated predecessor gap
The 0.80.4 update confirmation dialog already rendered GitHub release notes in a bounded `LazyColumn`, so touch scrolling existed. Its release-note rows were plain non-focusable Text/Spacer content and the list had no shared scroll-boundary indicators. On Android TV a D-pad therefore had no read-only release-note row targets to advance through, so focus-driven lazy scrolling could not provide the same browse behavior used elsewhere in VulkanScope. The panel also lacked the up/down scroll affordance already established on top-level pages and technical detail dialogs.

The 0.80.5 source verifier is run with version checking disabled against immutable 0.80.4. It fails specifically for missing release-note LazyListState ownership, TV browse rows and boundary indicators rather than merely failing on the successor version number.

## Current Android TV basis
Official Android documentation was rechecked on 2026-09-05. Standard Compose Foundation lazy layouts include focus-driven scrolling for TV and automatically keep focused lazy items visible. VulkanScope already pins Compose Foundation 1.12.0, which is newer than the documented 1.7.0 baseline for that behavior. 0.80.5 therefore retains standard Foundation `LazyColumn` focus scrolling and does not add custom D-pad key interception.

## 0.80.5 correction
The update flow retains the existing Material 3 Expressive visual language and action hierarchy.

- `ReleaseNotesContent` owns a `LazyListState`, explicitly retains user/touch scrolling and uses the shared `ScrollBoundaryIndicators` state contract.
- The release-notes viewport keeps the existing bounded 360dp update-dialog height and dark 20dp inner surface.
- Every non-blank/non-fence release-note row is emitted as its own lazy item and becomes a TV-only read-only focus target through the existing `tvBrowseModifier`. Focus uses the established rose/red outline and `BringIntoViewRequester` behavior.
- Markdown heading, body, bullet and quote typography/color semantics remain unchanged. A transparent 10dp row surface adds only the focus geometry and readable target spacing; it does not create a new capability/action state.
- Blank lines and code-fence delimiter lines remain spacing-only and do not consume D-pad focus.
- Update-dialog geometry remains 32dp, inner metadata/release-note cards remain 20dp, the banner remains a 24dp raised surface, and `Review`, `Download APK` and `Cancel` retain the existing action hierarchy.
- No custom `onKeyEvent`/`onPreviewKeyEvent` path is added to release notes; standard Compose focus navigation remains authoritative.
