# VulkanScope 0.41.45 Vulkan Video registry census audit

## Immutable predecessor
VulkanScope 0.41.44, ZIP SHA-256 `01d6953384471b1191d81a6ef59d74257cc1cab133cff2e9aee47a1e766314f7`.

## Demonstrated gap
0.41.44 queried exact but representative Vulkan Video capability profiles only. Khronos `vk.xml` provides machine-readable Vulkan codec `videoprofiles` member values and Khronos `video.xml` provides the corresponding StdVideo profile/level enums, so the sampled capability path left current canonical codec-member combinations unqueried.

## Locked sources
- Vulkan API registry: Vulkan 1.4.361 `registry/upstream/vk.xml`, SHA-256 `3ff4984b841932e04eebeb4ce2a6613ebd37c00ffb2e96549785b2c5d7da9e1d`.
- StdVideo registry: Khronos Vulkan-Docs `xml/video.xml`, exact content ref `content-sha256:d018b914014c06605e367a3b929670511e6f6de2f225c405a8b5e2d912408b76`, audited 2026-09-02, SHA-256 `d018b914014c06605e367a3b929670511e6f6de2f225c405a8b5e2d912408b76`.
- The Khronos registry documentation defines video.xml as the separate machine-readable source used to generate `StdVideo*` headers for externally defined video standards. It is not treated as the Vulkan API registry.
- Current Vulkan Video documentation defines `VkVideoProfileInfoKHR` general profile fields separately from codec-specific pNext members and documents four profile-specific failure returns for `vkGetPhysicalDeviceVideoCapabilitiesKHR`.

## Successor contract
The generated registry catalog uses vk.xml to choose valid codec-specific profile members and video.xml to verify their StdVideo identity/value and decode returned level values. Runtime capability enumeration is bounded to one explicit general profile, 4:2:0 8-bit, across 47 current codec-specific combinations. Exact success/unsupported/unavailable states are retained per combination; no codec-wide support inference is added. Video-format enumeration remains explicitly sampled.
