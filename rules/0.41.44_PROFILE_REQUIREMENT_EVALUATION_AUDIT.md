# VulkanScope 0.41.44 Vulkan Profiles requirement-evaluation audit

Immutable predecessor: VulkanScope 0.41.43 ZIP SHA-256 `48565d324d216f80f0278814047d19539cb32c05724411b36b55199430611ffa`.

## Demonstrated predecessor gap

VulkanScope 0.41.43 exposes Android Vulkan Profiles, Android requirement profiles, Khronos Roadmap profiles and LunarG minimum-requirements names. Android 15/16/17 use a small hard-coded evaluator, while Khronos Roadmap 2022/2024/2026 and LunarG minimum-requirements rows are effectively API-version-only partial evaluations. Android 2022/2021 are catalog-only. A profile row marked `UNKNOWN · partial evaluator` therefore did not mean that the full authoritative requirement graph had been checked.

Classification: `SPEC-MISSING`, `BUG`, `TEST-GAP`, `USABILITY`.

## Authoritative source lock

The normalized source contract is checked in as `registry/profiles/profile_requirements_lock.json` and is tied to Vulkan 1.4.361. Khronos Roadmap semantics are tied to `KhronosGroup/Vulkan-Headers` immutable release ref `v1.4.361`, path `registry/profiles/VP_KHR_roadmap.json`. Android requirement/profile semantics are tied to `KhronosGroup/Vulkan-Profiles` immutable release ref `v1.4.361` for the Android 15/16/17 and Android Vulkan Profile 2025 files. The current upstream definitions were rechecked during this release; no runtime network access is introduced.

Roadmap 2026 is normalized from its own exact capability composition. It does not blindly inherit Roadmap 2024's promoted-Vulkan-1.4 capability or Roadmap-2024 line-mode alternatives. Android 15's `subgroupSupportedOperations` requirement is BASIC|VOTE|ARITHMETIC|BALLOT|SHUFFLE|SHUFFLE_RELATIVE, mask `0x3F`.

LunarG minimum-requirements definitions are not byte/source locked in this release. Their catalog entries therefore carry no API-only support threshold and always remain explicit `UNKNOWN` coverage until an authoritative definition is pinned and normalized.

## Successor evaluator contract

- Feature requirements are identified by Vulkan structure plus member, not by member name alone.
- Property requirements implement explicit minimum, maximum, boolean equality, bitmask containment and vector-minimum semantics.
- Format requirements test required linear/optimal/buffer feature masks against queried `VkFormatProperties` evidence.
- Required-profile inheritance is evaluated recursively with cycle rejection.
- Alternative capability arrays use OR semantics: any complete alternative passes the group; all verified failures fail; any unresolved alternative keeps the group Unknown.
- Missing device/instance extensions become verified failures only when the owning extension enumeration completed Available. Otherwise the requirement stays Unknown.
- Checked-in Vulkan extension promotion metadata may satisfy an extension requirement only when the device API reaches the authoritative promoted core version.
- Verified requirement failure dominates and yields FAIL. Missing evidence, unmapped inherited profiles or incomplete mapping yields UNKNOWN. PASS is possible only when the mapped profile declares complete coverage and every requirement is verified.
- `VP_ANDROID_vulkan_profile_2025` remains coverage-limited because its complete official property/format matrix is not normalized in this release. Android 17 inherits that limitation. Android 15 inherits catalog-only Android 2022; Android 16 inherits Android 15. These profiles may produce verified FAIL but cannot produce a false PASS.
- Roadmap 2022/2024/2026 now perform feature/property/extension/OR checks rather than API-only evaluation, but retain `completeCoverage=false` until an independent generated source-equivalence gate proves every authoritative capability member. They therefore may produce verified FAIL while a non-failing result remains UNKNOWN.
- Android 2022/2021 and LunarG minimum-requirements profiles remain catalog-only UNKNOWN instead of receiving an API-only support claim.
- Profiles UI, Analysis, snapshot JSON, TXT and HTML use the same `vulkanProfileEvaluations()` result source.

## Regression evidence

`tools/verify_profile_requirements_04144.py --root <immutable 0.41.43>` is the failing-before-fix oracle and must fail. The same verifier must pass on 0.41.44. `tools/test_profile_evaluator_state_machine.py` verifies status precedence, directional limits, bitmasks, OR semantics and the complete-coverage PASS gate. `tools/test_profile_requirements_negative_mutations.py` rejects Android-15 mask drift, removal of the complete-coverage gate, Roadmap-2026 over-inheritance, a stale Profiles-UI source and a LunarG API-only claim, while an unrelated UI-text mutation is the false-positive control.
