# VulkanScope 0.80.14 PaddingValues compile audit

## Demonstrated failure
The user-supplied Windows release build reached `:app:compileReleaseKotlin` and failed at MainActivity imports with unresolved references `calculateBottomPadding` and `calculateTopPadding`. Native libadrenotools diagnostics before that point are warnings and did not terminate the build.

## Cause and repair
AndroidX Compose Foundation defines `calculateTopPadding()` and `calculateBottomPadding()` as public functions on the `PaddingValues` interface, not as package-level extension symbols that require imports. VulkanScope 0.80.13 called the functions correctly on `navigationPadding` but also imported nonexistent package-level names. 0.80.14 removes only those two invalid imports and retains both member calls unchanged.

## Non-regression
The 0.80.13 Material 3 Expressive presentation, Vulkan 1.4.362 registry/header baseline, 304 validated providers, 110 structs, 104 query groups, schema 2, technicalReport 3 and Database 0.39.27 compatibility remain unchanged. No native, registry, generated query, report or security/resource file is modified.

## Verification
The targeted verifier fails against immutable 0.80.13 with version checking disabled because the invalid imports are present, and passes on 0.80.14. Negative mutations restore each bad import, remove each required member call and regress release identity. The immutable 0.80.13 regression contract permits only the MainActivity import repair plus version metadata.

Android Gradle compilation after this repair is not claimed as PASS in the packaging environment; the user's build environment should rerun `:app:assembleRelease`.
