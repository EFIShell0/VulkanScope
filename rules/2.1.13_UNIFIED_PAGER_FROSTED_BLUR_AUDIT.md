## Failing-before-fix evidence
- The supplied 9.66-second 2.1.12 runtime video shows the single pager lagging its live scroll position and failing to settle cleanly back into its normal-flow placeholder.
- 2.1.12 independently tweened the pager overlay Y coordinate instead of using the live anchor offset directly, so the visual card could trail the list during both pin and reverse return.
- 2.1.12 rendered the header and compact bottom navigation with translucent tint-only backdrops; the requested actual backdrop blur was absent from those chrome surfaces.
- The pager join used a different multi-gradient tint stack and could repaint the header region, causing visible tone variation beside and around the pager during the join.

## Repair
- The active pager visual remains alive whenever its anchor is visible, including zero handoff progress, and the one overlay pager uses the anchor's live Y coordinate directly until the live header clamp applies.
- Independent pager-position and pager-glass-height tweening are removed. Scroll itself supplies continuous motion, while the existing top scroll-indicator stack animation remains unchanged.
- The pager overlay removes unmatched top/bottom wrapper padding and starts from a 72 dp placeholder estimate before live measured-height feedback, so its normal-flow landing geometry matches the placeholder.
- A retained crisp page layer and a retained blurred page layer are recorded once per draw pass at the app chrome host. The page replays only the crisp layer; the blurred layer is sampled only inside the app header and compact bottom navigation clips.
- Header and bottom navigation blur sampling uses live root coordinates, including landscape/system-navigation insets, and one shared uniform glass tint.
- The pager glass keeps its existing retained local blur but clips drawing below the live header boundary only, uses the same uniform tint as the chrome, and removes radial/vertical tint gradients.
- The pager card uses one opaque surface color in both normal and pinned positions so its own tone cannot darken from double translucent composition when joining the glass.

## Performance and safety boundary
- No PixelCopy, framebuffer readback, bitmap screenshot, `toImageBitmap`, per-frame bitmap allocation, network capability, permission, Vulkan query or native/JNI change is introduced.
- Retained GraphicsLayer command recording and bounded API-31 blur RenderEffects are used; the ordinary content layer remains crisp and blur draws are clipped to chrome/glass bounds.
- Manifest, native collector, registry/generated data, report/Database semantics, Turnip handling, dependencies, ABI set and packaged artwork remain predecessor-equivalent.
