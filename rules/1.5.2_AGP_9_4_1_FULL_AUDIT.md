## Authoritative current-baseline review
- Android Gradle Plugin: official Android Developers release documentation identifies 9.4.1 as the current stable patch on the 9.4 line at audit time. AGP 9.4 supports API 37 and requires Gradle 9.6.0 or newer. VulkanScope therefore moves 9.4.0 to 9.4.1 and retains its already-compatible Gradle 9.7.1 wrapper.
- AGP 9.4.1 patch notes include D8/R8 crash and performance fixes, a Windows invalid Kotlin module-name repair and an R8 nondeterminism fix where identical inputs could produce different DEX/mapping outputs. Because VulkanScope release builds enable minification and resource shrinking, this is a correctness/reproducibility relevant build-chain patch rather than a cosmetic version bump.
- Khronos Vulkan Registry/specification baseline remains Vulkan 1.4.364 / `VK_HEADER_VERSION 364`. The checked-in SHA-256-locked registry, pinned Vulkan-Headers commit, generated registry query manifest and Android query coverage remain unchanged.
- Android target/compile SDK remains 37. NDK remains stable r29 `29.0.14206865`. No speculative API, registry or native query migration is introduced.

## Crash, ANR and lifecycle audit
- Activity-scoped work remains under a `SupervisorJob` and is cancelled in `onDestroy`.
- Update check/download `Call` objects and jobs, Turnip file-manager scan work and the Vulkan probe process are explicitly cancelled/stopped during Activity destruction.
- Default-network and display listeners are unregistered in `onStop` and are guarded by registration flags before later re-registration.
- Vulkan probe work remains isolated in the non-exported service, uses a single bounded worker, bounded 64 MiB result handling, one-shot process ownership and `shutdownNow` during service destruction.
- No new polling loop, global coroutine scope, unbounded executor, native resource or background observer is introduced by 1.5.2.

## Memory and resource-bound audit
- Turnip archive input remains capped at 96 MiB and archive extraction retains path confinement, type validation and native-library read-only hardening.
- Analysis snapshots remain capped at 8 MiB and Database/report response readers retain their existing bounded read paths.
- Probe output remains capped at 64 MiB and terminal-result publication/teardown continues to be covered by lifecycle, timeout and cancellation regression gates.
- Registry, profile and report collections remain bounded by the existing generated catalog/manifest and resource-contract tests. No new persistent cache or collection was added.

## Security and privacy audit
- `allowBackup=false`, `usesCleartextTraffic=false`, `supportsRtl=true` remain explicit in the manifest.
- Providers and the Vulkan probe service remain non-exported. MainActivity remains the only intentionally exported application component.
- Permission set remains unchanged: INTERNET, ACCESS_NETWORK_STATE, REQUEST_INSTALL_PACKAGES and MANAGE_EXTERNAL_STORAGE. This release adds no permission.
- Database transport retains fixed HTTPS origin validation and disables HTTP and HTTPS redirects. Update transport retains the existing GitHub release boundary and package-name, signing-certificate and monotonically-newer-version validation before installation.
- Imported native driver libraries retain read-only enforcement before dynamic loading. ZIP/path traversal, symlink/canonical-path and bounded-size checks remain predecessor-equivalent.
- Static identifier review found no Android ID, serial, telephony identifier, MAC/account collection or WebView JavaScript bridge introduced by this release. No automatic upload is added.

## Reporting and Vulkan correctness audit
- Existing registry regeneration, Vulkan compile-regression, specification-regression, report-semantics, Surface-integrity, Profiles evaluator/source/negative-mutation and Vulkan Video census gates remain mandatory in the 1.5.2 quality route.
- Profiles continue to preserve met / verified-unmet / unknown accounting and category totals. Unknown/unavailable evidence is not converted to unsupported.
- Android Display/HDR evidence remains distinct from Vulkan `VkSurfaceKHR` formats, color spaces, present modes and presentation queues. A Vulkan surface color-space enum is not treated as proof of physical display gamut.
- JSON/TXT/HTML/Database reporting paths are production-byte identical to 1.5.1. No report field, capability mapping, extension name, profile requirement or query source changed.

## Accessibility and usability audit
- The four-tab bar remains 310 dp maximum width by 54 dp height. Four equal cells yield a 77.5 dp nominal cell width at the cap, so both dimensions exceed Android's documented 48 dp minimum interactive-target recommendation.
- Tabs retain Compose `Role.Tab` semantics and persistent visible text labels. The icon is decorative within the already-labeled tab, preventing duplicate accessibility announcements.
- Selection indication remains local, fully rounded and clipped with rectangular ripple indication disabled, retaining the 1.5.1 visual-overflow fix.
- RTL support remains enabled. Real TalkBack, Switch Access, large-font, keyboard/TV focus and hardware rotation replay remain runtime evidence classes and are not inferred as PASS from source checks.

## Performance and build audit
- Release `isMinifyEnabled=true` and `isShrinkResources=true` remain enabled. AGP 9.4.1 contains relevant D8/R8 correctness/performance repairs.
- Vulkan/native/report production code is byte-identical to 1.5.1; there is no runtime hot-path change to benchmark or justify speculatively.
- Gradle 9.7.1 is retained rather than expanding the change to the newer wrapper because it satisfies AGP 9.4's official minimum and the environment cannot execute a full Android build to validate an additional wrapper migration.
- Kotlin Compose plugin 2.4.10, compile/target SDK 37, NDK r29, ABI set and application dependencies remain unchanged.
