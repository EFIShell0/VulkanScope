# VulkanScope 0.41.26 Export Snapshot / Driver Mutation Audit

## Scope

- Re-audited VulkanScope 0.41.25 under `PROJECT_RULES.md` for report preservation, canonical Vulkan evidence, native/driver mutation security, lifecycle ownership, UI-thread blocking, memory pressure and release optimization.
- Vulkan registry/query semantics remain unchanged from the validated Vulkan 1.4.360 baseline.

## Corrected report export lifecycle

- TXT/HTML serialization moved off the Compose/main thread onto `Dispatchers.IO`.
- Export initiation persists the exact complete-report snapshot into VulkanScope private cache before external destination selection.
- Pending SAF state stores only saveable filename/path/MIME metadata; picker return consumes the persisted snapshot instead of regenerating from current mutable UI/report state.
- Destination writes stream from the snapshot with a bounded copy buffer and no report-sized `toByteArray` duplication.
- MediaStore publication remains `IS_PENDING` until a successful write. Failed known partial MediaStore, pre-Q Downloads and SAF destinations are deleted when the provider/filesystem permits.
- Snapshot cleanup covers success, cancellation, handled failure and bounded stale-cache cleanup.

## Corrected driver mutation lifecycle

- Complete-report mutation readiness is rechecked at driver picker launch, picker return, import entry and driver-mode mutation.
- Picker selection has an explicit in-flight guard independent of ZIP extraction state.
- Whole-bundle Turnip validation/hardening remains fail-closed but now runs only from IO context in settings status checks, driver validation and probe preparation.
- Full, Surface and ad-hoc collection entry points do not start new Vulkan work while a private driver import is in progress; deferred recollection is retained where needed.
- Successful Turnip import forces a fresh complete collection even when Turnip was already selected, preventing old-driver capabilities from remaining attached to the newly installed bundle.

## Optimization and ownership

- Removed the broad R8 keep rule for `MainActivity`.
- Static JNI protection now targets `VulkanProbeService` and its native member names, matching the three exported JNI symbols in `vulkanscope.cpp` while leaving the large UI class optimizable.
- Static JNI UTF ownership remains paired at 16 `GetStringUTFChars` / 16 `ReleaseStringUTFChars`; `ANativeWindow_fromSurface` / `ANativeWindow_release` remains 1 / 1.
- No new concrete native handle, FD or heap leak was identified by static review.

## Unchanged contracts

- Vulkan canonical naming, raw unknown values, partial `VK_INCOMPLETE` evidence, Surface/WSI state, multi-device attribution, schema-2 submission, schema-3 technicalReport, update security and Database endpoint policy remain unchanged.
- Android 17 Turnip native-code read-only extraction and whole-bundle hardening from 0.41.25 remain mandatory.
