# VulkanScope 2.1.0 UI, pagination, update-transfer and Database result audit

## Baseline
- Release identity: VulkanScope 2.1.0, versionCode 2100.
- Immutable predecessor: VulkanScope 2.0.6.
- Predecessor ZIP SHA-256: `aa1c41acde5399f17622c7506d69e0a85c586e0f32b840462cc1afbeabd306ff`.
- Predecessor source census: 700 files.
- Vulkan capability baseline remains Vulkan 1.4.364 with the existing locked registry, generated query manifest, native collector, validated extension coverage and report semantics.

## UI surface contract
- The application header remains the single shared header but is presented as a rounded, bounded, translucent surface rather than a hard rectangular opaque strip.
- Shared lazy pages expose soft top and bottom intersection fades only when more content exists in the corresponding direction. These visual fades must not consume input, change list state or hide data permanently.
- Search fields and cards inherit the same soft viewport-edge treatment because the effect is applied by the shared page container rather than by destructive clipping of individual controls.

## Turnip file-manager layout contract
- The file manager exposes one layout button whose icon always represents the current layout.
- Activating that button opens a bounded layout menu rather than permanently consuming toolbar width with one button per layout.
- Six layouts are available: List, Compact list, Detailed list, Grid, Dense grid and Large tiles.
- The most recently selected layout is persisted only as private UI preference metadata and restored when the manager is reopened. It does not affect imported driver bytes, driver selection semantics or archive validation.

## Large-list pagination contract
- `COLLECTION_PAGE_SIZE` is 50.
- Features, Formats, Properties & Limits and Extensions paginate the visible filtered result set at no more than 50 rendered rows/items per page.
- Filter/search changes reset the visible page to the first page and page indices are clamped after result-size changes.
- The shared pager keeps the established filter pager interaction language: previous arrow, editable page number, page count and next arrow.
- Pagination is presentation-only. Full Vulkan collection, in-memory report objects, TXT/HTML/JSON exports, Database payload generation, profile evaluation and analysis continue to consume the complete unpaginated data.

## Update transfer contract
- GitHub release asset size is retained from the already-authorized GitHub release metadata and provides a determinate denominator from the start of transfer when available.
- HTTP response content length remains accepted when supplied. Transfer progress is computed from actual bytes downloaded divided by the selected trusted total and is clamped to 0..100 percent.
- The visible progress bar fills continuously from zero to full width according to that percentage and shows a numeric percentage.
- When GitHub release metadata supplied an asset size, an asset-size mismatch is a hard failure and the completed downloaded byte count must match before the package proceeds. Existing release provenance, package identity, signing-certificate, versionCode/versionName and installer validation remain mandatory.
- No update endpoint, permission, package authority or trust rule is added or weakened.

## Database submission result contract
- Database submission remains explicit user action and keeps the existing fixed HTTPS endpoint, payload/privacy rules and 64-hex report-ID validation.
- Only after a validated successful submission, the result dialog shows the report ID inside a bounded surface with a dedicated copy action.
- The same success state exposes an `Open report` action using the existing external-link icon/button family and the existing public report URL builder.
- No report URL is synthesized from an unvalidated ID and no automatic browser launch is introduced.

## Preserved correctness boundary
- `VulkanProbeService.kt`, `AndroidManifest.xml`, native C++, registry query catalog, locked registry/generated manifest, `AdvancedAnalysis.kt` and `ValidatedExtensionCoverage.kt` remain byte-identical to 2.0.6.
- `app/build.gradle.kts` changes only versionCode/versionName.
- Production changes are limited to `MainActivity.kt`, two local vector layout icons and release identity.
- No Vulkan query, scheduler lane, probe ownership, timeout/cancellation, report schema/content, Database request schema, permission, network endpoint, ABI, dependency or build-chain version changes are permitted.

## Required evidence
- `tools/verify_release_2100.py` checks the source contract and immutable correctness hashes.
- `tools/test_release_2100_state_machine.py` covers paging boundaries, combined Properties/Limits paging, progress fractions, validated report-ID URL eligibility and layout persistence semantics.
- `tools/test_release_2100_negative_mutations.py` proves the release verifier rejects representative regressions in each requested feature and a protected native baseline mutation.
- Full static quality-gate execution, Android build attempt, deterministic dual-ZIP generation, clean extraction, exact package census/equality and clean-extract quality-gate rerun remain separate recorded evidence classes.
