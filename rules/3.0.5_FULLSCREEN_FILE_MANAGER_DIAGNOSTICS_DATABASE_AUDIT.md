# VulkanScope 3.0.5 Full-Screen File Manager, Diagnostics and Database Audit

## Scope

VulkanScope 3.0.5 is a bounded UI/workflow release over immutable VulkanScope 3.0.4 (`9be183e6863cbdfcea543faafa49404369f0cb297bfccd50b582d1adaec65c74`, 816 files). Production runtime changes are restricted to `MainActivity.kt` and `AdvancedAnalysis.kt`; `app/build.gradle.kts` changes release identity only. Manifest, native/JNI Vulkan collection, Vulkan registry/generated data, report/export schemas, permissions, ABI targets, dependency pins and the corrected 3.0.4 dependency graph remain predecessor-equivalent.

## Screenshot-driven file-manager findings

The supplied portrait screenshot showed the Turnip browser visually contained by an enclosing perimeter, a separate search row consuming vertical space and neutral folder-card outlines. The requested model is an independent full-screen section: true black app background, no outer browser border or rounded enclosing window, retained system-navigation region, View & sort followed immediately by an expandable search control, and Vulkan-red outlines around actual folder/file content cards instead of around the whole manager. The same shared browser hosts Analysis JSON/minimum/raw-report and Reports TXT/HTML storage operations, so those paths are routed through one full-screen overlay host instead of rendering local modal browsers.

## File-manager implementation

Turnip keeps its existing bounded scanner, ZIP validation, selection limit, breadcrumb model and import revalidation. Its manager surface is rectangular, true black and borderless. Open/close is rendered with fade plus bounded vertical slide; close first clears visibility and retains the state for 220 ms so the exit animation is visible before reset. The toolbar owns one View & sort button followed immediately by either the round Search action or, while expanded, the width-filling search field and explicit close action. Removing the separate search row returns vertical space to the listing. Folder and validated-ZIP row/grid cards use the Vulkan-red outline family.

The shared-storage browser now uses the same full-screen visual contract and one application-level overlay host. All existing import/export actions pass their unchanged validation/export callbacks into that host. The browser keeps canonical-path restrictions, extension allowlists, bounded 4096-entry scans, limited import size where specified, atomic temporary exports and overwrite confirmation. Portrait and landscape are responsive presentations of the same state; landscape keeps a bounded controls pane and dedicates the rest of the screen to the listing. Shared folder/file row/grid cards use the same Vulkan-red outline family.

## Diagnostic collection redesign

Diagnostic collection is separated into complete collection, high-level collection phases and probe/scheduler evidence. Timing display is centralized through `formatAnalysisElapsedTime`: values are clamped non-negative, seconds are shown to three decimal places and the exact millisecond count is included in parentheses. Scheduler wait remains explicitly distinct from probe execution time, and unavailable timing is not fabricated.

## Database lookup redesign

Database lookup exposes two explicit modes. Database list performs only an explicit user-triggered `GET /v1/reports` against the pre-existing fixed HTTPS VulkanScope Database host, requests at most 50 reports, uses the documented `beforeSubmittedAt`/`beforeId` cursor when loading more and bounds accumulated unique rows to 200. It reuses the existing bounded response reader, rejects malformed report IDs and filters already-fetched rows locally. Selecting a listed report feeds its ID into the same exact report comparison flow.

Report ID mode accepts exactly 64 lowercase hexadecimal characters and retains the existing compact public technical-report fetch and local comparison semantics. No new upload, mutation, permission or endpoint host is introduced.

## Evidence and build status

`tools/verify_release_3005.py` checks release identity, strict file census, full-screen/motion/toolbar/card anchors, all shared-storage routing, duration formatting, bounded Database-list semantics, retained 3.0.4 TV compile fix and protected-file hashes. `tools/test_release_3005_state_machine.py` exercises close retention, toolbar expansion, timing formatting and bounded Database list/cursor behavior. `tools/test_release_3005_negative_mutations.py` requires the verifier to reject representative regressions while accepting documentation-only audit growth. `tools/verify_release_3005_regression.py` enforces the production-byte boundary against the immutable 3.0.4 tree.

An Android Gradle compile was attempted in the artifact environment, but the wrapper cannot obtain Gradle 9.7.1 because `services.gradle.org` is not resolvable there. That attempt is therefore NOT a compile PASS and is not used as release evidence. The user's Android Studio environment remains the authoritative compile replay for this package.
