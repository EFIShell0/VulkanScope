## Demonstrated predecessor issues
- `USABILITY`: Properties & Limits and other chip-filter surfaces use plain horizontally scrolling strips that can hide later filters without an explicit directional affordance at phone width.
- `USABILITY`: evidence/property/query/limit counts are presented as dense flat sentences rather than the application's expressive metric hierarchy.
- `USABILITY`: the app provides no transient in-app indication when Android gains or loses a validated default network.
- `USABILITY/CORRECTNESS`: the Turnip bundle surface reports essentially installed/not-installed state and omits source ZIP provenance and standard AdrenoTools metadata already present in a selected package.
- `TEST-GAP`: the new shared filter behavior, validated-network state machine, Turnip provenance privacy boundary and responsive metric presentation were not represented by a release-specific failing-before-fix/negative-mutation contract.

## Corrections
All chip-style filters now route through one Material 3 Expressive LazyRow carousel with left/right arrow controls, RTL-aware physical direction, selected-item auto-visibility and standard focusable controls. Flat evidence count sentences are represented by width/font-scale-aware metric cards. `ConnectivityManager.registerDefaultNetworkCallback` observes only the Android default network; a connected state requires INTERNET plus VALIDATED capabilities and does not perform an application network probe. The validated-network authority is `NetworkCapabilities.NET_CAPABILITY_INTERNET` plus `NetworkCapabilities.NET_CAPABILITY_VALIDATED`. State transitions use a bounded 4.5-second polite-live-region banner with distinct connected/disconnected icon and color treatments.

Turnip imports record the SAF display name, URI, provider size/last-modified values when supplied and local import time in app-private preferences only. Installed `meta.json` is read authoritatively for schemaVersion, name, description, author, packageVersion, vendor, driverVersion, optional driver date, minApi and libraryName. The UI reports missing fields as not provided rather than guessing. The source URI/provenance keys are not consumed by technicalReport/TXT/HTML/Database serialization or Analysis snapshots.

## Non-regression boundary
Native Vulkan code, Vulkan 1.4.362 registry/header/generated query bytes, Vulkan Video exact-profile census, report serialization, update validation, Turnip extraction/security internals, Surface lifecycle, submission schema, ABI set and resource ceilings remain predecessor behavior. The only new permission is normal `ACCESS_NETWORK_STATE`; no new network endpoint or automatic upload is introduced.

## Retained-oracle repair record
During the final retained-gate pass, two historical source oracles were found to be successor-stale rather than production defects. The 0.80.6 live-region negative mutation originally targeted the first generic polite live region and could mutate the new network banner instead of the collection banner; it was made collection-specific. The retained 0.80.9 Details oracle expected an obsolete lowercase helper sentence while the preserved production UI uses the explicit `Use Details for full decoded/raw format evidence.` helper; the verifier and its false-positive fixture now require that exact current sentence. These repairs do not relax the retained behavior: the corresponding verifier, state model, negative mutation and unrelated false-positive controls all pass after repair.
