# VulkanScope 0.41.28 simple-feature completeness and isolated-crash audit

- Version: 0.41.28 / versionCode 438.
- Re-audited the simple extension-backed feature collector independently from the generic extension collector. The 0.41.27 verifier accepted generic extension-completeness markers even though `collectVulkanSimpleFeatureGroup` could still publish an Available root when one GPU exposed the requested extension and another GPU had incomplete/unavailable device-extension enumeration.
- Replaced the simple-feature root status/reason with scoped deferred tokens. Any uncertain device-extension enumeration now marks the owning simple feature group Incomplete while retaining positive per-device feature evidence.
- Strengthened `tools/verify_release.py` to isolate `collectVulkanSimpleFeatureGroup` and require the scoped incomplete-state propagation, preventing a marker in a different collector from satisfying the release gate.
- Re-audited isolated native crash handling. The crash marker is installed for all JNI probe entry points, but 0.41.27 only consumed it early for the base group. Non-base native crashes could therefore wait until their normal 12-30 second timeout and be misreported as a generic timeout.
- All probe groups now consume a native-signal marker immediately. Base keeps complete-checkpoint recovery; non-base groups publish explicit Unavailable crash evidence, stop the isolated process and continue through existing bounded cleanup.
- Vulkan registry, Android/Gradle/Kotlin/Compose pins and report/database schema contracts were rechecked without requiring a dependency or schema migration.
