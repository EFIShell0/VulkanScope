# VulkanScope 0.34.9 Material 3 Expressive Full-UI Audit

- Baseline: VulkanScope 0.34.8.
- Scope: full user-facing Compose surface, explicitly authorized for this release.
- Visual identity is preserved: black/dark-neutral surfaces, Vulkan dark-red `#A41E22`, rose accent `#E2676A`, existing typography hierarchy, destination structure and brand/vendor/HDR artwork.
- Application theming uses the official `MaterialExpressiveTheme` with `MotionScheme.expressive()` and the established VulkanScope color tokens and shape scale.
- Compose UI/Foundation/Animation are pinned to 1.12.0 and Material 3 to 1.5.0-alpha26 so the release can use the current official expressive APIs audited for this pass.
- Portrait primary navigation uses `ShortNavigationBar` / `ShortNavigationBarItem` without changing destination order or labels.
- The custom compact TV/landscape navigation rail remains in place because its focus acquisition and bring-into-view behavior are project requirements; its selected-state colors and existing expressive containers remain aligned with the application theme.
- App-bar actions use morphing expressive icon-button shapes while preserving 48 dp touch targets, 24 dp icons, semantics and placement.
- Search fields, filter chips, assist chips, Settings switches and driver radio selection are centralized through expressive wrappers using the existing palette and rounded shape language.
- Filter chips and icon buttons use current shape-morph APIs; selected filter state retains explicit check evidence.
- Dialog geometry and surfaces use the existing VulkanScope dark hierarchy; confirm/dismiss actions use morphing expressive button shapes with experimental opt-in kept at the wrapper scope.
- Startup/collection loading uses `LoadingIndicator`; linear progress presentation uses `LinearWavyProgressIndicator`; update and collection timing/behavior are unchanged.
- Update and collection banners use rounded expressive surfaces but keep the established non-modal status semantics and update-security flow.
- Dense instance/device layer, extension, Surface format/present support, memory and property/limit rows were normalized to the existing `CapabilityItemCard` / `CapabilityKeyValue` component hierarchy.
- Remaining functional navigation/action vectors were redrawn with rounded line-cap geometry. `ic_action_github.xml`, VulkanScope branding, GPU-vendor logos and HDR/data artwork remain untouched brand/data assets.
- No Vulkan query, 0.34.8 `VkFormatProperties3`/`VkFormatFeatureFlags2` propagation, report schema, TXT/HTML export, Database submission, Turnip/SAF, update endpoint, APK verification, ABI policy or native collection behavior is intentionally changed.
- Source-code comments remain forbidden.
- Release verification must validate the version, expressive dependency baseline, theme/motion/navigation APIs, expressive loading/progress APIs, absence of legacy portrait `NavigationBar` and direct legacy progress components, functional icon round-cap geometry, XML well-formedness and existing Vulkan/report/security gates.
