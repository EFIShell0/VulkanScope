# VulkanScope 0.41.29 base completeness, extension-state and Turnip traversal audit

- Version: 0.41.29 / versionCode 439.
- Published/query and pinned compile-header baseline: Vulkan 1.4.360 dated 2026-08-14, Vulkan-Headers commit `0b7f383797fa7be53ae28213e001ae60668ee511`.
- Found that native `baseReportComplete` was derived only from physical-device enumeration. Per-device device-extension enumeration could remain incomplete/unavailable while the report became complete, allowing missing runtime extensions to escape automatic scheduling and eventually permitting a falsely exhaustive export/submission. The marker now requires every device extension catalog to be Available, with a Kotlin defense-in-depth gate enforcing the same condition.
- Found that no-match extension and simple-feature collectors collapsed device-extension `VK_INCOMPLETE` to Unavailable. They now preserve Incomplete for partial enumeration, reserve Not applicable for completed absence, and retain Unavailable for genuine enumeration failure without complete applicability evidence.
- Found that extension-dependent advanced groups could omit optional/chained fields while retaining an Available root when device-extension enumeration was uncertain. `queue2`, `format2`, `imageFormat2`, `external`, `sparse`, `memory2` and `videoCapabilities` now become Incomplete in that case while retaining bounded positive data.
- Replaced legacy Turnip `walkTopDown().toList()` validation with a streaming stack. Every child consumes the shared 2048-entry budget and is canonicalized/confined/type-checked before any directory descent; symlink-like canonical aliases and special entries fail closed without whole-tree materialization.
- Turnip import/backup transaction directory names now use UUIDs; import requires a newly created directory so a stale timestamp-named directory cannot be reused if the wall clock repeats.
- Database schema 2, technicalReport schema 3, report hash, fixed Database endpoint, ABI set and Vulkan baseline are unchanged.
