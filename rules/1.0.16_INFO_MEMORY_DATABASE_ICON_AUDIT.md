## Requested evidence and classification
The supplied real-device screenshots demonstrate that Application and Developer still use generic list/person glyphs, Memory heaps and Memory types reuse the same processor-like memory symbol, Run Vulkan self-tests uses a generic laboratory flask, and Check for updates includes an unwanted lower tray/short line. These are `USABILITY` defects. The requested Database verification is a `CORRECTNESS` / `TEST-GAP` boundary because visual work must not silently break report submission or public-report lookup.

## Production repair
Application section identity uses an exact crop of the shipped horizontal VulkanScope SCOPE wordmark. The VulkanScope version row reuses the shipped adaptive-launcher foreground artwork without tint. Developer uses a local code glyph, Memory heaps and Memory types use separate local RAM glyphs, Run Vulkan self-tests uses a chip/check diagnostic glyph, and Check for updates uses a dedicated line-free downward arrow while update download retains its existing download/tray affordance.

No native Vulkan query, report field, capability classification, Database serialization field, endpoint, permission, updater validation, Turnip path or resource ceiling is changed by this release.

Submission remains explicit POST `/v1/reports` with schema 2 and schema-v3 `technicalReport`; public report retrieval remains explicit GET `/v1/reports/<64-hex>?compact=1` and requires a `technicalReport` object. The application retains the 2 MiB no-truncation ceiling.
