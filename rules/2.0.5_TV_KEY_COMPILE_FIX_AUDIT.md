# VulkanScope 2.0.5 Android TV key-input compile-fix audit

## Scope
- Correct the release Kotlin compile failure introduced by the 2.0.4 Android TV long-press implementation.
- Preserve the requested Android TV OK/Enter long-press evidence dialog behavior without relying on unavailable Compose key-event APIs.
- Keep all 2.0.4 collection, scheduler, Vulkan, report, security and desktop-pointer behavior unchanged.

## Build failure reproduced from user evidence
- `:app:compileReleaseKotlin` failed at `MainActivity.kt` because `androidx.compose.ui.input.key.nativeKeyEvent` was unresolved.
- Native/CMake compilation for arm64-v8a, armeabi-v7a and x86_64 had already completed before the Kotlin failure.
- The libadrenotools diagnostics shown before the Kotlin error are compiler warnings and are not the cause of this release failure.

## Requirements
- Source must not import or reference `KeyEvent.nativeKeyEvent`.
- Android TV activation matching must use supported Compose key input APIs. DPAD center, Enter and numpad Enter remain direct Compose keys; select/A compatibility may use the public `Key.nativeKeyCode` bridge.
- Long press must be time-bounded and must not require platform repeat-count or Android native-event access.
- A short activation press must not open the evidence dialog or be consumed by the long-press detector.
- Once the long-press threshold is reached, the existing Evidence provenance/actions dialog opens once and the corresponding release is consumed to prevent duplicate activation.
- The long-press coroutine must be tied to Compose lifecycle through `rememberCoroutineScope`; no global scope, thread, executor or persistent timer may be introduced.
- 2.0.4 scheduler concurrency, one-query-per-process isolation, native collector, registry/generated data, report/Database behavior, permissions, network policy, ABI set, AGP and Gradle versions remain unchanged.

## Implemented design
- Uses `KeyEvent.key`, `KeyEvent.type`, `Key.DirectionCenter`, `Key.Enter`, `Key.NumPadEnter` and `Key.nativeKeyCode`.
- A first key-down starts a 550 ms coroutine timer and returns false so normal short-press behavior remains available.
- Key-up before the threshold cancels the timer and remains unconsumed.
- Reaching the threshold opens the existing evidence dialog and marks the hold consumed; the release event is then consumed and the state is reset.

## Evidence expectations
- Kotlin source contains no unresolved `nativeKeyEvent` import/reference.
- Targeted source/state/negative-mutation tests reject reintroduction of the unavailable API, loss of supported TV activation keys, immediate short-press dialog opening or removal of bounded timer cancellation.
- The 2.0.4 scheduler and Vulkan/report/static quality gates remain mandatory.
