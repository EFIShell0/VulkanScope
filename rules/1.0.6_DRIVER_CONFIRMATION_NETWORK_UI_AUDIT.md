## Demonstrated defects
- `BUG`: the Settings Turnip source card opened the manager but never called the shared source-switch request, so a valid active Turnip driver could remain visually and functionally stuck behind the selected System source.
- `BUG` / `TEST-GAP`: default-network callbacks synchronously re-read active-network capabilities. Android's NetworkCallback documentation warns that synchronous `getNetworkCapabilities`/active-network reads during callbacks are race-prone; the supplied runtime report that some connection cuts produced no transition is consistent with that race class.
- `USABILITY`: the 1.0.4 carousel continuation overlay used an 85% black rectangular edge gradient and is visibly harsh in the supplied real-device screenshot.
- `USABILITY`: collection-disabled driver controls did not explain beside the selector why driver switching is unsafe during an active report.
- `CORRECTNESS` / `USABILITY`: System↔Turnip switching and managed Turnip activation could commit immediately without an explicit confirmation.
- `USABILITY`: Turnip Details/Remove and common dialog Close actions did not share the requested established Material 3 Expressive affordances.

## Repair scope
Only `MainActivity.kt` production behavior is changed. Network callback state now consumes callback evidence, source changes and slot activation are confirmation-gated, collection lock rationale is visible, Turnip source selection requests the real mode change, shared action affordances are reused, and carousel edge treatment is softened. Version metadata advances to 1.0.6/1006. Native Vulkan, report serialization, Database schema/envelope, Turnip archive/provenance security, manifest permissions, dependency pins and registry/generated data remain unchanged.

## Evidence boundary
Khronos latest Registry was rechecked on 2026-09-08 and remains Vulkan 1.4.362 dated 2026-09-04. Android's current `ConnectivityManager.NetworkCallback` documentation explicitly warns against synchronous capability/link-property reads inside callback methods and documents ordered `onAvailable` followed by `onCapabilitiesChanged` from API 26 onward. Source/state-machine evidence can close the demonstrated callback architecture defect; only an actual device reconnection/disconnection rerun can be labeled runtime reproduction PASS.
