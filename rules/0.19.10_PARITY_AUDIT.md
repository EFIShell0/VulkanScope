# VulkanScope 0.19.10 parity audit

The implementation basis is the VulkanScope project rules as shipped with 0.19.9, the VulkanScope registry rules, and the current Khronos Vulkan 1.4.357 specification baseline referenced by those rules. No CapsViewer rules file is used as an engineering requirement.

The validated native query catalog is synchronized with its checked-in generated manifest and coverage snapshot. The catalog now contains 107 explicitly validated physical-device structures and 74 validated runtime query groups.

The extension-detail layer retains exact runtime extension enumeration and only runs optional feature/property queries when the selected extension is actually enumerated. The parity layer now mirrors all physical-device feature/property structures referenced by CapsViewer 4.12 extension readers that are not already covered by the registry-driven 1.4.357 query catalog or promoted core Vulkan paths. This adds 259 additional parity structures validated by the canonical Vulkan-Headers 1.4.357 compilation baseline and their consumed field names without treating registry presence or database entries as runtime support.

Unknown, unavailable and unsupported states remain distinct. Registry presence is not treated as runtime support. Optional query failures remain isolated from the base inspection path.

This revision closes the previously identified CapsViewer 4.12 vendor-specific feature/property gaps for the structures present in its dedicated extension readers and available to the Vulkan 1.4.357 compilation baseline. Every parity field is consumed by the native report serializer, while fields that cannot be represented safely are emitted as explicit unavailable/raw values instead of being guessed. Promoted core capabilities remain owned by their core query paths and are not double-counted as extension capabilities.


Parity source basis: CapsViewer 4.12 extension readers were used only as a compatibility reference. VulkanScope engineering requirements remain defined exclusively by the VulkanScope rules files. Current Khronos Vulkan 1.4.357 is the canonical specification baseline.


## Android compilation parity sanitization

CapsViewer-referenced structures are compiled only when their canonical Vulkan-Headers 1.4.357 definitions exist in the Android compilation baseline. Promoted alias structure types sharing the same VkStructureType numeric value are represented by one canonical runtime case to avoid duplicate switch labels while preserving the queried data. QNX and OHOS-only structures are not compiled into Android; they remain unavailable rather than being guessed.
