## Demonstrated usability and state gaps
The supplied 0.80.3 device screenshots and source inspection identify five release-scoped gaps without requiring a Vulkan query/schema change:

1. Format and extension rows open substantial detail dialogs but the row itself does not expose a visible detail affordance, so clickability is discoverable only by trial.
2. Format detail content can scroll but has no boundary indicators, while extension detail content is not vertically scrollable at all. Long extension registry metadata can therefore be clipped below the dialog viewport.
3. Extensions uses the shared lazy page, but its detail-capable entries are not explicit TV browse targets. The shared lazy surface also does not state the user-scroll contract explicitly.
4. Android TV read-only browsing requires D-pad focus to move through visible evidence and bring focused content into view. Detail-capable Format/Extension cards and modal key/value evidence must participate in the same focus/bring-into-view contract used elsewhere.
5. Collection UI previously treated completion of the work queue as a successful collection regardless of whether a complete, meaningful Vulkan base report exists. A timeout, fatal report error, no-device result, incomplete base report, or completely unknown/empty device evidence must not receive the same success presentation as a valid completed report.

## 0.80.4 corrections
- Format and Extension detail-capable rows retain whole-card activation and add a consistent Material 3 Expressive `Details` affordance. The affordance changes discoverability only; it does not change Vulkan evidence or make a previously read-only row mutable.
- Format and Extension detail dialogs use one bounded `ScrollableDetailDialog` with `ScrollState`. Up/down indicators use actual scroll boundaries: top hides Up, bottom hides Down, and non-scrollable content hides both.
- Extension and Format pages retain the shared top-level `LazyColumn`; touch/user scrolling is explicitly enabled. No nested vertical lazy list is introduced.
- On Android TV, detail-capable rows use the existing `tvBrowseModifier` focus/BringIntoView contract. Modal capability rows retain the same read-only TV browse behavior. Standard Compose Foundation lazy-layout focus-driven scrolling remains the primary D-pad mechanism; this release does not add speculative key interception that would steal focus movement.
- The compact in-progress collection chip is icon-only. The adjacent explanatory status text may remain, but the chip itself no longer repeats `Collecting information...`.
- Collection status now has an explicit `FAILED` state. `COMPLETED` is shown only when a report has no fatal error, has an authoritative complete base report, contains at least one physical device, and contains meaningful device evidence. Null report, timeout/fatal error, incomplete base report, zero devices, or an all-unknown/all-empty device result shows a red X and `Failed` instead of the green success state.
- Optional/deferred query failures do not automatically convert an otherwise valid complete base report into global collection failure. Existing per-query Unknown/Unavailable/Not applicable evidence remains authoritative at its own scope.

## Regression evidence requirements
- `tools/verify_detail_tv_collection_0804.py` must fail against immutable 0.80.3 and pass against 0.80.4.
- `tools/test_detail_tv_collection_0804_state_machine.py` must cover successful/failed collection classification and modal boundary-indicator states.
- `tools/test_detail_tv_collection_0804_negative_mutations.py` must reject removal of detail affordance, modal vertical scrolling, modal boundary indicators, Android TV browse focus, collection failure classification, and icon-only collecting status. An unrelated descriptive-text mutation is the false-positive control.
- `tests/golden/0.80.3_regression_contract.json` locks predecessor production bytes and allows only the demonstrated `MainActivity.kt` UI/state behavior, the new X drawable, and version metadata.
- Existing Vulkan registry/spec/query, report/Surface, Profiles, Vulkan Video, 0.80.0 hardening, 0.80.2 Encyclopedia and 0.80.3 search-crash contracts remain mandatory.

## Evidence-class boundary
Source/static/state-machine tests do not substitute for Android TV hardware traversal, touch-device visual validation, Android compilation, or real-device collection failure reproduction. Those classes are reported separately and remain NOT EXECUTED unless actually run; they may be called PASS only when actually executed.
