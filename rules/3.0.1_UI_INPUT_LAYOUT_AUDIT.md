# VulkanScope 3.0.1 UI, Input and Layout Audit

## Immutable predecessor and failing-before-fix evidence
- Immutable predecessor: VulkanScope 3.0.0, 796 files, ZIP SHA-256 `c34d7093bc2e52da7e5f11c167018103fb1cbff0413bc0941314c17cc7618a44`.
- The supplied landscape shared-storage export screenshot shows the browser viewport compressed to a shallow strip because header, description, search, export-name and footer controls are vertically stacked above/below it.
- The supplied Overview screenshot shows the first rounded page surface entering the translucent top chrome at rest instead of remaining visibly separated from the header.
- Source inspection of 3.0.0 shows the opening rule reaches scale 1.0 at phase 2 and then shrinks to 0.88 and 0.58 in later phases before fade-out.
- Source inspection of 3.0.0 also shows a custom evidence-row secondary-click path beside a generic long-press detector; desktop secondary input therefore requires interception before gesture interpretation, not only hiding the quick menu.
- Post-fix hardware/device replay is not available in this packaging environment and is not claimed PASS.

## Current Android/Compose research
- Current Android Compose gesture documentation describes the Initial pointer-event pass as the parent-first interception pass and states that custom raw pointer handlers must explicitly consume pointer changes when they own a gesture.
- Current Android large-screen input guidance identifies mouse/trackpad input as normal large-screen input and exposes raw `PointerEvent` handling for advanced pointer behavior.
- Existing VulkanScope platform evidence continues to use documented ChromeOS ARC and Android PC-form-factor feature signals only; no Googlebook product identity is inferred.

## Classified production changes
- `USABILITY/OPENING`: keep the completed accent rule at full scale until fade-out and remove the inherited duplicate local `lineWidth` declaration.
- `USABILITY/FILE-MANAGER`: use a two-pane shared-storage browser in landscape >= 700 dp, with bounded scrollable controls on the left and the existing lazy folder/file viewport taking the full right-pane height.
- `USABILITY/INPUT`: intercept secondary-mouse-button sequences at the Initial pass for ChromeOS ARC / Android PC environments so right click is a no-op before long-press or quick-menu gesture logic can react.
- `USABILITY/FEEDBACK`: animate a file-manager-tone red border together with the existing press-in/press-fill evidence-row hold feedback.
- `REGRESSION/CHROME`: replace the 3.0.0 10 dp header underlap with a 12 dp positive page/header separation while preserving the sticky pager's real header clamp.

## Security, semantics and performance boundary
- Native Vulkan collection, JNI, reports, Database submission, export contents, Turnip validation/install semantics, registry data, manifest permissions, endpoints, ABI targets and dependency versions remain predecessor-equivalent.
- The file-manager layout still uses the same bounded shared-storage root, validation, atomic write and overwrite confirmation paths; only presentation geometry changes.
- Secondary-click suppression adds no identity heuristic and no new permission. It relies only on already-audited documented platform feature evidence.
- No framebuffer capture, PixelCopy, bitmap allocation, extra blur pipeline or new background task is introduced.
