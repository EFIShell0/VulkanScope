## Vulkan query and reporting audit

The validated Vulkan 1.4.360 core paths, runtime extension enumeration, Vulkan 1.1-1.4 feature/property structures, validated extension feature/property mappings, 64-bit VkFormatProperties3 handling, queue/memory/format data, Surface/WSI data, Display/HDR evidence and registry coverage remain present. No additional Vulkan 1.4.360 physical-device query gap was identified in this audit.

The complete DeviceReport/RegistryCoverage datasets continue to feed the application UI and the complete TXT, HTML and structured Database report paths. Unsupported, unavailable, not-applicable and unknown evidence remains distinct.

## Updater security fixes

0.35.0 allowed an in-flight update check or APK download to continue after Direct GitHub updates were disabled. It also accepted any intersection of signing-history certificate sets and could leave a completed but rejected APK in the private cache.

0.35.1 cancels active OkHttp calls and coroutine jobs when direct updates are disabled, clears pending installer state, prevents installer launch after opt-out, deletes failed APK targets, and verifies signing lineage direction correctly. Multi-signer packages require exact current signer-set equality.

## Resource and lifecycle audit

Display listeners are registered/unregistered with Activity start/stop lifecycle. Activity coroutine work is cancelled at destruction. Update calls/jobs are explicitly cancelled. Native Surface and ANativeWindow ownership paths retain explicit destruction/release, Vulkan instances are destroyed, and dynamically loaded Vulkan libraries are closed by VulkanApi ownership. No known deterministic native or Kotlin resource leak was identified by static review.

This audit does not claim device-profiler proof of zero leaks; runtime heap/ASan/LeakCanary testing remains a release-device validation requirement under PROJECT_RULES.
