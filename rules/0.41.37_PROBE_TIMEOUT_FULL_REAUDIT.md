# VulkanScope 0.41.37 probe-timeout full re-audit

## Classification

- `REGRESSION / BUG`: the 0.41.36 terminal handoff behavioral fixture modeled `.done` only after service/JNI return, but native base collection can publish its terminal JSON before that return boundary. The device timeout therefore remained outside the behavioral oracle.
- `MEMORY / RESOURCE / RACE`: Vulkan object/loader cleanup was not uniformly process-owned even though all native collection executes in the dedicated probe process, the next query did not prove the previous process had exited before reusing the probe slot, and hard timeout termination depended on `ActivityManager.runningAppProcesses` observing the secondary process. An OEM-visible-list miss could leave a JNI-blocked executor alive.
- `USABILITY`: a deterministic terminal timeout/unavailable result could still consume a second 45-second base retry.
- `TEST-GAP`: producer death after pre-return durable publication, no-service-return terminal consumption, stale-process reuse and coroutine/activity cancellation while JNI is blocked were absent from the 0.41.36 state-machine fixture.

## Successor behavior

The terminal base JSON and exact `.done` sidecar become durable before native teardown. Vulkan loader, instance and surface teardown are deferred to the dedicated process boundary. The service may self-kill after terminal publication is durable, and it independently arms a hard-deadline watchdog at the exact consumer timeout plus 100 ms so JNI-blocked work cannot survive merely because `ActivityManager` omitted the PID. The consumer settles for 150 ms at its timeout boundary before final cleanup/return, covering the watchdog deadline. Service `onDestroy` is also a process-owned cancellation boundary: an explicit `stopService` destroys the dedicated process even if its executor is blocked inside JNI. `runServiceProbe` handles non-timeout `CancellationException` through `NonCancellable` teardown, waits the bounded stop settle/quiescence path, deletes request files only after teardown is driven, and then rethrows cancellation. The main process also kills/waits out any visible stale `:vulkan_probe` process before the next request. Base timeout is 20 seconds; terminal unavailable/timeout is not repeated, while a single retry remains for explicit non-timeout `incomplete` partial-positive evidence.

## Behavioral evidence

`tools/test_probe_timeout_state_machine.py` covers terminal result + marker surviving producer death before consumer polling, unrelated-marker false-positive rejection, deterministic timeout non-retry, bounded incomplete partial-evidence retry, stale-process barrier semantics, and a PID-discovery-failure case where the service-owned hard-deadline watchdog still guarantees process death before the consumer settle window ends. `tools/test_probe_cancellation_state_machine.py` separately models cancellation with a hung JNI worker, no ActivityManager PID visibility, process-owned `stopService`/`onDestroy` exit before request-file cleanup, cancellation rethrow, and an unrelated-process false-positive control.
