## SECURITY / PERFORMANCE — bounded raw Turnip archive input
0.41.46 bounded ZIP entry count, decompressed aggregate bytes and per-file bytes, but the raw bytes read from the user-selected content URI before decompression had no ceiling. An arbitrarily large untrusted archive could therefore consume prolonged I/O/CPU even when extracted output eventually remained within the 64 MiB aggregate bound.

0.80.0 wraps the selected archive stream in a 96 MiB consuming-input bound before `ZipInputStream`. The existing canonical-path confinement, duplicate-path rejection, 2048-entry limit, 32 MiB per-file limit, 64 MiB decompressed-total limit, private temporary directory, read-only native-library hardening and cleanup-on-failure rules remain unchanged.

Failing-before-fix: `tools/verify_full_hardening_0800.py --root <immutable 0.41.46>` reports the missing raw archive bound and exits non-zero.

## BUG / MEMORY / PERFORMANCE / CRASH-RISK — checkpoint materialization and terminal classification
0.41.46 reread every changed probe checkpoint into a Kotlin `String` and constructed a full `JSONObject` tree before the service-owned `.done` marker. A checkpoint may approach the existing 64 MiB publication ceiling, so repeated growing snapshots created avoidable main-process allocation/GC pressure and could increase OOM/ANR risk, especially on 32-bit or memory-constrained devices. The same helper used `optString("status", "unavailable")`; therefore a syntactically valid base checkpoint with neither an explicit terminal status nor `baseReportComplete=true` could be misclassified as terminal during timeout-boundary recovery.

0.80.0 makes normal polling metadata-only. It records length/mtime/inode changes, immediately re-enters crash handling when required, and otherwise waits for the service-owned terminal marker. Terminal publication validation uses strict streaming `JsonReader` parsing in the main process and defaults missing status to no terminal evidence rather than fabricated `unavailable`. Full publication bytes remain available only at bounded terminal, crash or timeout recovery boundaries. Service-side strict streaming validation and single terminal-marker ownership remain unchanged.

## Security surface re-audit
The reviewed production surface retains cleartext disabled, backups disabled, a non-exported FileProvider constrained to the private update cache, a non-exported isolated Vulkan probe service, official GitHub release provenance checks, bounded APK downloads, package/signing/version validation, fixed HTTPS Database root, redirect prohibition for Database submission, explicit user-initiated submission, private Turnip storage, canonical ZIP path validation, duplicate-path rejection, no WebView/JavaScript bridge, and native `-fstack-protector-strong` plus RELRO/NOW hardening.

No additional concrete path traversal, arbitrary network endpoint, automatic upload, exported-component, update-signature bypass, persistent identifier, unbounded Vulkan enumeration allocation or static native ownership defect was demonstrated by this audit. This statement is a static/source and regression-gate result, not a claim that no vulnerability can exist.
