# VulkanScope 0.41.34 real release compiler regression audit

## Supplied compiler evidence

The connected Android release build compiled the native translation unit for arm64-v8a, armeabi-v7a and x86_64 and failed on the same source defects: `swapchainColorspaceAvailable`, `surfaceExtensionAvailable`, `androidSurfaceExtensionAvailable` and `instanceExts` were undeclared in the base collector. The same build also promoted an unused `hasExt` lambda to an error because VulkanScope compiles its native source with `-Werror`; this is the supplied unused hasExt compiler failure. Kotlin compilation independently failed with `Unresolved reference 'kv'` at the Device layer enumeration HTML export.

## Repair

The base collector now performs the already-bounded instance-extension enumeration before creating its zero-extension base instance and derives the three advertised WSI booleans plus `instanceExts` from that evidence. Missing `VK_KHR_get_physical_device_properties2` is described as not advertised only when enumeration is complete; otherwise the report preserves uncertainty. The unused `hasExt` lambda is removed. Device layer enumeration HTML export uses the existing `table(...)` helper.

## Regression proof

`tools/verify_compile_regressions.py` fails against 0.41.33 and passes against 0.41.34. The 0.41.33→0.41.34 golden contract permits production changes only in `vulkanscope.cpp` and `MainActivity.kt`; Vulkan registry/header pins, 302-extension/110-struct coverage, schema 2, technicalReport 3, Database compatibility, resource ceilings, timeout/race behavior and security policy remain unchanged.
