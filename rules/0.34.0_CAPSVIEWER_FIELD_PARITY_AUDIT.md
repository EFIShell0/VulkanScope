# VulkanScope 0.34.0 CapsViewer 4.12 Field-Level Parity Audit

The 0.33.10 follow-up audit initially flagged ten mapped structures as missing field consumers. Re-inspection against Vulkan 1.4.360 showed those structures use EXT/KHR/core aliases that share canonical VkStructureType values and are already consumed by the corresponding promoted/alias switch cases. The remaining real gap was VK_EXT_host_image_copy pointer-backed layout arrays.

0.34.0 implements the Vulkan count/allocate/fill query pattern for VkPhysicalDeviceHostImageCopyPropertiesEXT::pCopySrcLayouts and pCopyDstLayouts, enforces a 65536-entry bound per list, removes generic pointer-placeholder output for those members, and presents each layout with canonical VkImageLayout naming plus its raw value. Unknown future values remain explicit raw unknowns.

The existing generic property pipeline carries these values to application UI, TXT, HTML and structured technicalReport/Database output.
