# VulkanScope 1.5.3 overlay and navigation obstruction audit

## Scope
- Resolve compact-navigation misalignment on devices where Android's own navigation controls occupied the same lower screen region as the VulkanScope floating compact tab bar.
- Ensure transient collection/connectivity/update overlays and the bottom navigation bar do not obstruct the first or last actionable controls on vertically scrollable capability pages.
- Preserve all 1.5.2 Vulkan/spec/report/security/runtime behavior; this release is a targeted UI usability and accessibility correction only.

## Requirements
- Compact bottom navigation must remain 54 dp tall with the existing 310 dp max width and 48 dp+ touch targets, but it must sit above Android navigation controls by applying the real bottom navigation-bar inset in addition to the existing 4 dp gap.
- Main vertically scrollable capability pages must reserve dynamic top clearance equal to the currently rendered transient-overlay stack height plus a small visual buffer. When multiple overlays are visible, the clearance grows; when overlays collapse, the clearance returns accordingly.
- Main vertically scrollable capability pages must reserve dynamic bottom clearance equal to the rendered compact-bottom-navigation host height plus the established content gap so that the final visible button/card can be scrolled fully above the floating bar.
- Scroll indicators must use the same dynamic top/bottom clearances so their affordances do not appear under the overlay stack or behind the bottom navigation host.
- No new runtime permissions, network paths, guessed hardware data, native ownership changes, collection/report schema mutations or security regressions may be introduced.

## Implemented design
- `CompactBottomNavigationBar` now adds `WindowInsets.navigationBars` bottom padding before applying the floating 4 dp gap.
- `TransientStatusOverlayHost` collapses its outer vertical padding to zero when nothing is visible, avoiding a permanent blank reserved strip, and its measured height is propagated to page content as a composition-local top inset.
- The measured compact-bottom-navigation host height is propagated to page content as a composition-local bottom inset.
- `VulkanLazyPage` now uses these live insets for `LazyColumn` content padding and for scroll-boundary indicator placement.

## Evidence expectations
- On a three-button-navigation handset, the compact tab bar no longer overlaps Android's system navigation buttons.
- On Overview and other `VulkanLazyPage` destinations, the last buttons/cards can be scrolled fully above the floating compact tab bar.
- While collection/network/update banners are stacked at the top, the first card is pushed below them; after banners disappear, the content returns upward without remaining hidden or clipped.
- This release intentionally does not mutate Vulkan registry data, JNI/native collection, Database schema/export content, updater verification or AGP/Gradle versions.
