# VulkanScope 0.41.38 terminal ownership race audit

## Real-device failure signature
0.41.37 published `base report complete checkpoint and terminal marker published before process-owned teardown`, then `VulkanProbeService.onDestroy` and the worker both issued `Process.killProcess(Process.myPid())` in the same millisecond. The UI immediately reported `The dedicated Vulkan base probe signaled completion with malformed or non-terminal JSON.` A replacement `:vulkan_probe` process started immediately afterward.


Immutable predecessor ZIP SHA-256: `99ca00817dee7d0f2a0c5ab6b99df02e56072fa2bd87876dcdb5af4586404052`.

The real-device sequence contains two separate SIGKILL ownership paths in the same millisecond. The new verifier provides failing-before-fix evidence against immutable 0.41.37 before the production patch is accepted.

## Classification
- BUG / REGRESSION: native `.done` publication occurred before JNI/service return while the writer lifecycle was still active.
- RACE / LIFECYCLE: normal polling could promote terminal-shaped JSON before `.done` and kill the producer.
- RACE / RESOURCE: worker completion and `onDestroy` owned independent self-SIGKILL paths.
- TEST-GAP: the previous state machine modeled pre-return terminality as valid instead of distinguishing durable checkpoint evidence from terminal ownership.

## Failing-before-fix
`tools/verify_probe_terminal_ownership.py --root <immutable 0.41.37>` fails for native terminal-marker ownership, duplicate final publication, multiple process-exit sites, pre-marker normal acceptance, missing bounded service-marker reread and missing terminal-ownership behavioral test.

## Successor contract
0.41.38 makes `.done` service-owned and post-JNI only, validates terminal JSON by bounded streaming parse, retains native pre-return final checkpoints only for timeout/crash recovery, prevents base JNI duplicate final rewrite, and funnels hard-timeout/normal/cancellation process exit through one atomic claim.
