# VulkanScope 1.0.18 compile / full retained audit

## Classification
- `BUG/REGRESSION`: `PhysicalDeviceSelector` retained an old positional `ExpressiveFilterBar(..., selectedIndex, onSelected)` call after `arrowTint: Color` was inserted before the callback parameter. Kotlin therefore attempted to bind `(Int) -> Unit` to `arrowTint` and failed release compilation.
- `TEST-GAP`: the shared compile-regression gate covered earlier default-parameter mistakes but did not cover this `ExpressiveFilterBar` call site.

## Fix
- Release identity: 1.0.18 / versionCode 1018.
- Immutable predecessor: VulkanScope 1.0.17; ZIP SHA-256 `b6bce30aa467651b900102147573c91b3772dc1f48c6c2b91fd398ebe359034a`; 470 files.
- `PhysicalDeviceSelector` now binds the callback as `onSelected = onSelected`; `arrowTint` keeps its default value and no UI geometry or behavior changes.
- `tools/verify_compile_regressions.py` now rejects restoration of the compile-breaking positional call.
- A release-specific verifier, state machine and negative-mutation suite cover callback binding, release identity, Android hardening, probe lifecycle/resource invariants, Vulkan registry lock, Database routes/schema/ceiling and release optimization flags.

## Current upstream/spec audit
- Khronos current registry checked on 2026-09-09: Vulkan 1.4.362 / Registry 1.4.362, published 2026-09-04. VulkanScope remains pinned to the matching local registry SHA-256 `cf31c965cf6e788697139601da0c7e02a75a9b6c7ac764e7641f5521ffd9da06` and Vulkan-Headers commit `ee2ec5fd83dafce291024683b50dc89219333076` / header 362.
- Android target/compile SDK remains 37, minSdk 24, NDK 29.0.14206865 and the required arm64-v8a / armeabi-v7a / x86_64 ABI set.
- AndroidX Core 1.19.0 and Compose UI/Foundation/Animation 1.12.0 remain current stable upstream releases for the pinned release line; no dependency change is introduced by this compile fix.

## Security / privacy
- Cleartext traffic remains disabled and application backup remains disabled.
- VulkanProbeService and FileProvider remain non-exported.
- Database and update network roots remain fixed HTTPS origins; Database upload remains explicit user-initiated and report fields are not selectively omitted.
- No new permission, endpoint configurability, WebView, JavaScript bridge, broad storage permission or background upload path is introduced.
- Release native hardening remains stack protector + hidden visibility + RELRO + NOW; VulkanScope-owned native code remains `-Wall -Wextra -Werror`.

## Memory / crash / performance
- The isolated Vulkan probe service retains one serialized worker, bounded timeout, canonical cache-path confinement, service-owned Surface release, watchdog removal, executor shutdown and dedicated-process termination.
- Timeout, cancellation, terminal-result publication, malformed-result replacement, Surface lifecycle and driver-surface rebind contracts remain retained mandatory gates.
- The pinned libadrenotools dependency may emit upstream compiler warnings and contains process-lifetime allocations, but VulkanScope's custom-driver loader executes in the dedicated one-shot probe process and does not enable the upstream GPU-mapping import path; process termination bounds those third-party allocations. No VulkanScope-owned persistent leak was identified by the retained resource/lifecycle contracts.
- No native Vulkan collection, pNext scheduling, report serialization or recomposition query path is changed in 1.0.18.
