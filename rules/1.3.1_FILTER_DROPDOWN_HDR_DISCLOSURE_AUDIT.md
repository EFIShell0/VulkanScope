# VulkanScope 1.3.1 filter dropdown and HDR disclosure audit

## Triggering request
The user requested that Core-style single-select filters stop using the horizontal carousel and instead use a dropdown selector with in-menu search, a maximum of 50 entries per page, previous/next controls and direct page-number entry while retaining the existing All switch. The user also requested an explanatory line above HDR artwork identifying the artwork as the official format logos used for HDR types detected on the device and explaining why HLG and HLG+ remain text.

## Upstream evidence
Android `Display.HdrCapabilities` remains the authority for display HDR-type evidence. The current Android API reference defines Dolby Vision=1, HDR10=2, HLG=3, HDR10+=4 and HLG+=6, with HLG+ added in API 37. VulkanScope continues to render only types produced by that evidence path and does not infer HDR support from artwork.

The HLG/HLG+ disclosure is intentionally bounded to VulkanScope's authoritative asset policy: those types remain text because VulkanScope has no authoritative official-logo asset for them. The statement does not create capability evidence and does not alter Android's reported type list.

## Filter presentation change
`ExpressiveFilterBar` keeps its public selection-index behavior but routes specific single-choice selection through `ExpressiveSingleFilterSelector`. Search is case-insensitive. The filtered result set is paged at 50 entries. Previous/next page actions are bounded, and numeric page input only changes page when the requested page exists. Selecting an item returns the original label index to the existing callback.

When an All-first filter is active, the standalone All switch remains authoritative and the selector is disabled. Turning All off selects the first specific option through the existing callback behavior. Multi-select usage filters retain `ExpressiveFilterCarousel` because their interaction model is not single-selection.

## Immutable boundary
The immutable predecessor is VulkanScope 1.3.0. Runtime changes are limited to `MainActivity.kt` plus `ic_expand_more.xml`; `app/build.gradle.kts` changes only versionCode/versionName. Native/JNI code, AndroidManifest, report schemas, registry/query data, Database/update/storage behavior, ABI configuration and dependency pins remain predecessor bytes.

## Evidence boundary
Only the targeted 1.3.1 source contract, pure state model, negative mutations, predecessor regression boundary and release-package integrity are required for this requested pass. Android compile/lint/unit/device execution remains a separate evidence class and is not represented as PASS unless actually executed.
