# VulkanScope 0.41.41 Surface / binary-property / provenance audit

## Evidence and classification
Immutable predecessor: VulkanScope 0.41.40, SHA-256 `b85f3df2a78496be08dd8634ac94d0e97732e1e7f32524dd6e8d72ad9475deb2`.

The supplied Turnip comparison demonstrates a real Surface evidence regression: the new report records `vkCreateAndroidSurfaceKHR failed. VkResult=-1000000001`, after which previously populated Surface capabilities, presentation queues and Surface format/color-space rows are absent. Khronos defines that VkResult as native-window-in-use evidence, not unsupported capability.

The supplied comparison also demonstrates binary-field corruption: fixed 16-byte UUID properties are rendered as character-like output instead of the predecessor raw-byte form. Source inspection localizes this to generic integral-array streaming of `uint8_t`.

A separate source audit finds generated extension properties deduplicated by field name alone. That can erase struct provenance when promoted/core and extension property structs expose same-name members.

Categories: REGRESSION, BUG, REPORTING, LIFECYCLE, DATA-INTEGRITY.

## Successor behavior
0.41.41 routes fixed `uint8_t` arrays to exact raw-byte serialization. Generated property merge identity includes section plus name and preserves distinct struct provenance while upgrading equivalent manual extension rows to canonical struct provenance.

Surface callbacks carry the concrete Surface identity. A stale destroy cannot clear a newer Surface. Surface generation tokens gate merge of asynchronous probe results. Surface-only events during active collection set a pending Surface refresh instead of a pending full report collection. Enrichment consumes the matching pending refresh when it already probes the same live generation. `VK_ERROR_NATIVE_WINDOW_IN_USE_KHR` receives at most one delayed retry while the Surface is still valid; repeated failure remains Unavailable.
