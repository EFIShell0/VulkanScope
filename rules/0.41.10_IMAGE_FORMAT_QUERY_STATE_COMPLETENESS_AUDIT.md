# VulkanScope 0.41.10 Image Format Properties2 tuple-state completeness audit

## Trigger

A cross-driver Compare could show a historical successful `VK_FORMAT_S8_UINT` Android Hardware Buffer tuple against `Unknown / Not reported`. For a current producer, that wording was ambiguous: it did not distinguish a returned Vulkan error from a tuple variant that was intentionally not attempted because its prerequisite external-memory extension was not enumerated.

## Specification result

`vkGetPhysicalDeviceImageFormatProperties2` returns `VK_SUCCESS` for a successful exact query and may return `VK_ERROR_FORMAT_NOT_SUPPORTED` when the exact format/type/tiling/usage/flags combination is unsupported. With `VkPhysicalDeviceExternalImageFormatInfo`, handle compatibility is part of that exact query. A missing device extension is not itself proof that an image-format tuple is unsupported.

## Correction

0.41.10 keeps successful Image Format Properties2 payloads in `detailedProperties` and expands the separate bounded `imageFormatQueryResults` dataset into a complete scheduled tuple-state ledger.

- `available` records a completed query with `VkResult=0`.
- `unsupported` records only `VK_ERROR_FORMAT_NOT_SUPPORTED` (`-11`).
- `unavailable` records another non-zero `VkResult` without reclassifying it.
- `not_applicable` records an external-handle variant that was not attempted because its defining prerequisite device extension was not enumerated. No Vulkan result is fabricated.
- Base tuples are always attempted when the format itself is valid for the runtime query catalog.
- OPAQUE_FD and Android Hardware Buffer queries remain independent from base-query success.
- Successful detailed-property payloads and the tuple ledger use the same canonical tuple name.

The fixed recipe remains `VK_IMAGE_TYPE_2D`, `VK_IMAGE_USAGE_TRANSFER_SRC_BIT | VK_IMAGE_USAGE_TRANSFER_DST_BIT | VK_IMAGE_USAGE_SAMPLED_BIT`, and `flags=0`. A tuple result is not generalized beyond that recipe.

## Turnip-specific audit relevance

Current Turnip behavior may change across Mesa revisions. VulkanScope therefore does not infer S8/AHB support from the GPU name or from an older report. When the AHB prerequisite is exposed, the driver is queried and its exact result is preserved. When the prerequisite is absent, the tuple is explicitly Not applicable rather than silently missing.

## Reporting and compatibility

UI, TXT, HTML, Analysis snapshots and Database technicalReport preserve the ledger. Properties & Limits totals continue to count actual detailed properties/query diagnostics only. Submission schema 2, technicalReport schema 3 and the Vulkan 1.4.360 header/query baseline remain unchanged.

## Toolchain freshness

AGP 9.3.2 and Android API 37 are retained. NDK `29.0.14206865` remains the stable r29 baseline. Gradle is updated from 9.7.0 to 9.7.1 within the required 9.7.x family.
