# VulkanScope 3.0.8 D-pad, Analysis, Metrics and File Manager Audit

## Scope and immutable predecessor

VulkanScope 3.0.8 starts from immutable VulkanScope 3.0.7 (`df0775953977837dc7e6a004e275d99e39f89170b990f70b9a72928dd63372a0`, 831 files). Production runtime changes are restricted to `MainActivity.kt`; `app/build.gradle.kts` changes release identity only. Native/JNI Vulkan collection, `AdvancedAnalysis.kt`, `VulkanDependencyGraph.kt`, manifest, registry/generated data, report/export schema behavior, Database routes/bounds, permissions, ABI targets and dependencies remain predecessor-equivalent.

## Supplied visual and interaction evidence

The supplied Properties screenshot shows the current statistical summary as a long stack of large neutral cards above the pager. The requested presentation is the denser, accent-led summary language already established by the newer Quality/Diagnostics surfaces. The common metric components are therefore the change point rather than one page-specific duplicate, keeping Properties, Limits and other metric-driven destinations visually consistent in both portrait and landscape.

The supplied 16.4-second Android Studio/device-mirror video demonstrates repeated arrow-key/remote attempts without the expected downward focus/scroll progression. The 3.0.7 source explains the mismatch: lazy-list, lazy-grid, root-page and focus-card D-pad behavior was explicitly disabled unless `Configuration.uiMode` reported `UI_MODE_TYPE_TELEVISION`. Hardware Android `KEYCODE_DPAD_*` input is not exclusive to that uiMode; emulators, desktop/Googlebook-style environments and attached remotes/keyboards may deliver those keycodes while the UI remains phone/tablet/desktop classified. 3.0.8 removes that form-factor gate and handles the key event itself as the capability signal.

The navigation repair remains focus-first. When Compose can move to the next semantic focus target, it does so. Only when the next target is outside the current viewport does the list/grid perform a bounded animated scroll and retry focus. ScrollState-backed dialog/detail surfaces use the same principle with a bounded fallback. File-manager lists/grids, filter lists and other non-primary lazy surfaces are included so the fix is not limited to one screenshot page.

## Analysis and reference presentation

Quality, dependency-graph and self-test/result section headings now have distinct shield, graph and self-test identities rather than falling through to the same generic information glyph. No score, graph traversal or self-test semantics are changed.

Requirements is reorganized around an explicit registry-versus-runtime evidence boundary. It shows SATISFIED, NOT SATISFIED, UNKNOWN and checked totals, the checked-in Depends/Requires/Promoted-to relationship when present, and exact per-token runtime evidence. It still evaluates individual tokens only and never infers global support from a registry expression.

Minimums separates bundled Vulkan Profile evaluation from the local custom-minimum builder. Profile cards show status plus mapped/met/failed/unknown counts and available failure/unknown evidence. The custom builder keeps the existing bounded rule grammar and confirmation flow while making identity, syntax, saved profiles and current PASS/FAIL/UNKNOWN totals legible as separate concepts.

The Encyclopedia remains offline and registry-backed. Its redesign adds census metrics, category/search context, evidence-boundary guidance, entry-field guidance and semantic entry icons. The registry baseline and search/result bounds are unchanged.

## Database and file-manager presentation

Database report-list GPU identity now reuses the exact `SystemDriverVendorBadge` visual used by the Turnip/System driver settings rows. Identity still comes only from the explicit report `vendor_id`; unknown IDs retain the unknown-vendor asset.

Turnip and shared-storage file managers keep their full-screen AMOLED presentation and animated search. Directory changes now use bounded content transitions, breadcrumb segments animate active/inactive state, and Turnip selected/remaining counters animate exact integer changes. Storage access, canonical root checks, selection limits, ZIP validation and import/export mutation behavior remain unchanged.

## Evidence boundary

`tools/verify_release_3008.py` locks the requested source anchors and protected hashes. `tools/test_release_3008_state_machine.py` exercises the uiMode-independent D-pad model, bounded focus/scroll fallback, metric-grid responsiveness, requirement/minimum state counts and file-manager motion states. `tools/test_release_3008_negative_mutations.py` requires targeted regressions to fail while a documentation-only mutation remains accepted. `tools/verify_release_3008_regression.py` limits production drift to `MainActivity.kt` and the release identity.

Android `assembleRelease` and post-fix remote/device replay are independent evidence. The local execution environment cannot claim either result unless they are actually executed successfully.
