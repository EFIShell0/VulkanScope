# VulkanScope 1.3.0 Vulkan registered-mark and library-license audit

## Triggering request
The user requested that VulkanScope keep its product name unchanged while every human-facing use of the Vulkan API name is presented as Vulkan®, and that every library shown under Info expose its license through the same contained/right-chevron interaction hierarchy used by Details.

## Presentation correction
The release adds one bounded display-only replacement rule for the standalone API word `Vulkan`. It explicitly excludes `VulkanScope` and already marked `Vulkan®`. Shared navigation, destination, section, action, metric, evidence and detail presentation paths use that display rule. Curated explanatory/reference text that is directly presented to the user is likewise rendered with the registered mark.

The underlying evidence model is not rewritten. Canonical query/report keys including `Vulkan Query Status` and `Vulkan Query Safety`, raw Vulkan section identifiers, `VK_*` tokens, `Vk*` type names, extension names and native collection inputs remain predecessor values. Copy/share/raw serialization continues to operate on source evidence rather than the decorated display string.

## Library-license disclosure
Info > Libraries retains the direct dependency identities and versions already pinned by the build. Each row now includes license metadata and a contained `License` chevron affordance. Selecting it opens a bounded dialog with text artwork, the library/license identity, scrollable markdown-style content and a contained Close action using the existing X artwork.

The license documents are packaged under `app/src/main/assets/licenses/`. AndroidX/Compose, OkHttp and ZXing use Apache License 2.0; libadrenotools uses BSD 2-Clause; Vulkan Headers is disclosed under Apache-2.0 OR MIT. Runtime license viewing performs no network access.

## Immutable boundary
No Android permission, manifest entry, dependency version, ABI, native/JNI source, registry/query catalog, report schema, Database/update origin, storage behavior or updater behavior is changed by 1.3.0. The only runtime Kotlin change is MainActivity presentation/license UI; the only runtime additions are finite license text assets.

## Evidence boundary
Source-level release verification, a pure presentation/license state model, regression-contract verification and negative-mutation testing are required. Android compilation, lint, unit tests and real-device UI/accessibility behavior are separate evidence classes and are recorded as NOT EXECUTED when the required toolchain or device is unavailable.
