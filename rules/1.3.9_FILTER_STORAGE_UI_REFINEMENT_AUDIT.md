# VulkanScope 1.3.9 Filter / Storage UI Refinement Audit

Scope is intentionally limited to the user-reported filter popup, complete-report TXT/HTML presentation, in-app shared-storage browser presentation/type lock, Turnip file-manager view modes and interaction clipping.

## Confirmed predecessor problems
- Filter transient state could be destroyed by live label-list changes; popup positioning was not sufficiently tied to selector geometry and Back handling could dismiss the popup while the search IME was active.
- Complete-report TXT/HTML actions used a weighted side-by-side layout through an animated permission wrapper; on real-device layout this could leave one action effectively missing.
- Shared-storage export did not visually separate immutable file type strongly enough from editable base name.
- Turnip view switching exposed only List/Compact text choices and selection/press treatment needed stricter clipping to clickable shapes.
- Runtime storage explanatory copy referred to removed legacy architecture instead of describing only the current workflow.

## 1.3.9 decisions
- Keep popup/search/page state independent of mutable filter labels and anchor the popup using `PopupPositionProvider` selector bounds.
- Set popup Back dismissal false and explicitly clear focus while IME is present before closing the popup.
- Render TXT and HTML as two full-width actions on every layout size.
- Derive one fixed export extension from the request, edit only `filenameBase`, display the extension separately and reconstruct/validate the final name at save time.
- Provide four icon-only Turnip modes: List, Compact, Grid and Details, with local packaged vector resources.
- Clip every affected click/selection surface before `clickable`; make package cards selectable so selected state and actionable geometry match.
- Remove legacy storage-architecture wording from runtime copy while retaining historical rule documents.

## Non-goals
No Vulkan query/native/JNI/report-schema/Database/updater/permission/storage-confinement/Turnip-validation/dependency/ABI/API change is authorized by this release.
