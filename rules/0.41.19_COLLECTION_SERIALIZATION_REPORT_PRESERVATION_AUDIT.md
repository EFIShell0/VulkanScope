# VulkanScope 0.41.19 Collection Serialization and Report Preservation Audit

## Scope
- Probe scheduling and timeout ownership.
- Surface refresh/report merge concurrency.
- Complete-report task gating.
- Neutral source/report naming and release-package hygiene.
- Vulkan 1.4.360 / Android API 37 baseline revalidation.

## Corrections
- Added one application-side mutex around every isolated service probe so only the active probe consumes its timeout window.
- Prevented a timed-out probe from killing another independently queued native query by eliminating concurrent service-probe waiters.
- Surface refresh now merges into the newest report in the same collection generation rather than a stale captured snapshot, preventing newer detailed query evidence from disappearing.
- Full recollection is deferred while ad-hoc or Surface collection tasks remain pending and automatically starts when those tasks finish.
- Removed forbidden third-party comparison-product naming from source identifiers, runtime report section labels, tools, rule/audit filenames and release metadata while retaining the validated query coverage under neutral terminology.
- Updated report-label sanitation for the neutral internal coverage prefix so internal provenance wording does not leak into user-facing canonical Vulkan labels.
- Removed the nested registry README from the source release and strengthened the verifier to reject README.md/release.md at any depth and any fastlane directory.

## Baselines
- Khronos published registry/specification: Vulkan 1.4.360, 2026-08-14.
- Android compile/target API: 37.
- AGP: 9.3.2; Gradle wrapper: 9.7.1.
- Submission schema: 2; technicalReport schema: 3.
- ABIs: arm64-v8a, armeabi-v7a, x86_64.

## Verification intent
- Release verifier must reject regression of probe serialization, stale Surface overwrite protection, pending-task recollection gating, forbidden naming, nested README/release metadata, or baseline/version pins.
- Final ZIP must be re-extracted and reverified before publication.
