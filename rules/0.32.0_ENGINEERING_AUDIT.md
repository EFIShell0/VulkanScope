# VulkanScope 0.32.0 engineering audit

## Scope
The 0.31.1 application tree was audited across Kotlin/Compose UI and lifecycle code, isolated Vulkan probe IPC, native Vulkan ownership paths, Surface handling, Turnip ZIP/runtime loading, update/download validation, TXT/HTML export, Database submission, build configuration, generated registry coverage, and release verification.

## Fixed
- Turnip runtime fallback could select the first JSON and then the first shared object. Runtime loading now requires the validated `meta.json` declaration, a plain `.so` filename, and canonical confinement under the private bundle directory.
- Database submission previously depended primarily on the human-readable report body for future parsing. The schema-v2 envelope now additionally carries a schema-v3 structured technical report preserving raw numeric masks, query states, exact extension names/spec versions, layer extension lists, memory, queues, formats, Surface diagnostics, Profiles and registry coverage.
- The app-side 16 MiB submission allowance disagreed with the deployed Database worker's 2 MiB request limit. The client now uses the deployed 2 MiB limit and refuses oversized full reports without truncation.
- TXT/HTML export parity gaps were closed for display modes, queue video codec-operation bits, Surface diagnostics and presentation queues. HTML also gains instance-layer extension detail and Vulkan Profile evaluation/catalog data.
- Standalone HTML no longer maps `available` to the supported-green class; availability and support have distinct semantic colors.
- Settings and Info action buttons now use a shared high-quality icon-card component rather than inconsistent raw buttons.
- Native linker options explicitly request RELRO and immediate binding in addition to the existing stack protector, hidden visibility and 16 KiB page-size flags.

## Current specification baseline
Native compilation is pinned to official Vulkan-Headers v1.4.360 and verifies `VK_HEADER_VERSION == 360`. The checked-in generated exhaustive query metadata is intentionally not relabeled: it remains the validated Vulkan 1.4.357 / VulkanCapsViewer 4.12 query catalog. This prevents newly introduced registry structures from being guessed or mislabeled as queried. Runtime-enumerated extension names remain exact and unknown/unvalidated structures remain unknown rather than unsupported.

## Ownership and crash/leak review
The main activity owns a lifecycle coroutine scope and cancels it during destruction. Vulkan probes run in a separate process/service with bounded files and timeout cleanup. Native Surface and instance destruction paths were reviewed for matching release/destroy operations. No deterministic leak was identified in the audited ownership paths. This is a static audit, not a substitute for LeakCanary/ASan/device stress testing.

## Build-validation boundary
The original 0.31.1 archive contained the Gradle wrapper JAR/properties but omitted the `gradlew` and `gradlew.bat` launch scripts. Release 0.32.0 restores both scripts. Invoking the restored wrapper attempted to download Gradle 9.7.0, but the audit environment had no external network access and no Android SDK installation, so an Android/NDK APK build could not be completed here. Release verification therefore uses the checked-in verifier plus syntax/structure audits and records this limitation rather than claiming a build that did not run.
