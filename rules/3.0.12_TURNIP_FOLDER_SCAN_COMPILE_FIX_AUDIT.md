# VulkanScope 3.0.12 Turnip Folder Scan Compile Fix Audit

## Scope
VulkanScope 3.0.12 starts from immutable VulkanScope 3.0.11 (`746a625d4108a8b9839393bb3b4d4c1e89880ec237a663a24748624a32a43da3`, 851 files). Production runtime change is restricted to `MainActivity.kt`; `app/build.gradle.kts` changes release identity only.

## Failing-before-fix evidence
The supplied Windows `:app:assembleRelease` log reaches Kotlin compilation and fails at `MainActivity.kt:1142` with `Suspension functions can only be called within coroutine body`. The failing expression is the suspend `inspectTurnipArchive(nested)` call inside the non-suspend `children.asSequence().mapNotNull { ... runCatching { ... } }` folder-mapping lambda introduced by the 3.0.11 validated-count repair. The libadrenotools lines are warnings and are not the build-stopping error.

## Repair
The folder mapping was rewritten as an imperative `for (child in children)` loop in the existing suspend `scanTurnipFileManagerDirectory` function. `inspectTurnipArchive` is now invoked directly from the suspend function body while the existing directory-stream bounds and exact validated-count semantics are preserved. `CancellationException` is explicitly rethrown, ordinary per-folder exceptions are skipped, and `ensureActive()` remains in both outer and nested loops.

## Preserved behavior
The 3.0.11 rule remains authoritative: only direct child `.zip` candidates that pass `inspectTurnipArchive` increment `validZipFileCount`; the 256-candidate bound and limited-count indicator remain; an already-imported but otherwise valid Turnip archive remains counted; import-time ZIP validation remains authoritative. Vulkan/native collection, reports, Database, registry data, permissions, ABI targets and dependencies are unchanged.

## Evidence
`tools/verify_release_3012.py` rejects reintroduction of the non-suspend Sequence/runCatching pattern around the suspend inspector and locks the validated-count/cancellation contract. `tools/test_release_3012_state_machine.py` models folder success/failure/cancellation and the 63-ZIP/3-valid case. `tools/test_release_3012_negative_mutations.py` proves the verifier rejects the failing lambda form, cancellation swallowing and extension-only counting. `tools/verify_release_3012_regression.py` restricts production drift to the requested compile repair and release identity. Android Gradle compilation is reported separately and is not inferred from static evidence.
