# VulkanScope 1.5.5 landscape safe-width audit

## Scope
- Correct the remaining landscape page-width issue where right-edge cards and their chevron/action regions extended into the Android system-navigation strip.
- Preserve 1.5.4 compact landscape bottom-navigation sizing and 1.5.3 obstruction-aware top/bottom spacing.
- Avoid any Vulkan, report, security, native, permission or build-chain behavior change.

## Requirements
- The shared vertically scrollable page container must honor Android navigation-bar side insets, not only top/bottom spacing, so visible page content never renders under a right-side navigation strip in landscape.
- Scroll indicators must use the same safe horizontal bounds as page content.
- The correction must apply through the shared page scaffold rather than by hard-coding one destination card, so all `VulkanLazyPage` destinations benefit consistently.
- No changes to registry/header locks, JNI/native ownership, Database schema/content, network policy, update verification or build-chain versions are permitted.

## Implemented design
- `VulkanLazyPage` now reads `LocalLayoutDirection` and adds `WindowInsets.navigationBars` left/right padding to its `LazyColumn` content padding.
- `ExpressiveScrollHints` placement inside `VulkanLazyPage` now uses the same start/end inset offsets, keeping arrows within the same safe visual column as the page content.

## Expected evidence
- In landscape on three-button-navigation devices, right-edge Overview destination cards no longer place subtitle text or chevron buttons underneath the vertical system-navigation strip.
- Other `VulkanLazyPage` destinations inherit the same safe-width correction automatically.
- The floating compact bottom-navigation bar and top transient overlay spacing continue to behave as established in 1.5.4 and 1.5.3.
