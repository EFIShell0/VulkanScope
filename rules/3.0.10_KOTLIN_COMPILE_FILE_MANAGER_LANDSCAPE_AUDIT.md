# VulkanScope 3.0.10 Kotlin Compile and File Manager Landscape Audit

## Scope and immutable predecessor

VulkanScope 3.0.10 starts from immutable VulkanScope 3.0.9 (`8af4a85286b9102004e43dc22495f7003cc16c96deff788354d2025e5750132c`, 841 files). Production runtime changes are restricted to `MainActivity.kt`; `app/build.gradle.kts` changes release identity only. Native/JNI Vulkan collection, registry/generated data, report/export schemas, Database endpoints and bounds, manifest, permissions, ABI targets, packaged assets and dependency versions remain predecessor-equivalent.

## Failing-before-fix evidence

The user-supplied `:app:assembleRelease` log completes native builds for arm64-v8a, armeabi-v7a and x86_64 and then fails `:app:compileReleaseKotlin` at `MainActivity.kt:17773` with unresolved reference `LocalContext`. The predecessor uses fully qualified `androidx.compose.ui.platform.LocalContext.current` throughout the same source file but the new Database timestamp renderer introduced one unqualified use without importing `LocalContext`.

The shared File Manager landscape path places the View & sort chooser inside the left vertically scrollable controls pane. Its anchored Material dropdown therefore depends on the scrollable parent/anchor popup path that is not used in portrait and is the only orientation-specific interaction difference relevant to the reported non-responsive layout button.

## Repair boundary

The Database timestamp renderer now reads `androidx.compose.ui.platform.LocalContext.current` explicitly, matching the established source-file pattern and removing the missing-import dependency without changing timestamp parsing or presentation semantics.

The File Manager View & sort chooser is detached from the orientation-specific scroll container after activation. The trigger remains in the same toolbar location, but choices render in a bounded application dialog that is independent of portrait/landscape parent layout, uses system-bar insets, supports pointer and D-pad scrolling, preserves all six view modes and all sort modes, and closes only through the existing red X action. Outside tap and Back dismissal remain disabled to preserve the established X-only chooser contract.

## Evidence boundary

`tools/verify_release_3010.py` locks release identity, the LocalContext compile repair, the orientation-independent View & sort overlay and protected predecessor-equivalent files. `tools/test_release_3010_state_machine.py` models orientation-independent chooser activation and X-only dismissal. `tools/test_release_3010_negative_mutations.py` proves the missing-context reference and landscape chooser regressions fail while a documentation-only mutation remains accepted. `tools/verify_release_3010_regression.py` restricts production drift to `MainActivity.kt` and release identity.

The user-provided native warnings are warning-only libadrenotools diagnostics and are not the reported Kotlin build failure. Android Gradle compilation, `assembleRelease`, device landscape replay and real pointer/remote interaction remain separate evidence classes and may be called PASS only when actually executed successfully.
