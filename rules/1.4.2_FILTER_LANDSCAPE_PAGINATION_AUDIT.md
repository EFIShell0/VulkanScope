# VulkanScope 1.4.2 Filter Landscape and Pagination Audit

## Classification
- `USABILITY`: the supplied landscape screenshot shows the expanded single-filter container consuming almost the full available vertical window, leaving the pagination footer partially outside the visible area.
- `USABILITY`: the pagination controls are distributed across the full footer width because the `/ pageCount` text owns weighted space rather than participating in one centered control group.
- `USABILITY`: the editable page field is fixed at 96 dp even though the requested page entry needs only two digits.
- `PACKAGE/HYGIENE`: the user explicitly requires future VulkanScope source ZIPs to omit the top-level `screenshots` directory.

## Upstream check
- Android's current adaptive-layout guidance requires responsive layouts to adjust to changing display dimensions rather than assuming one fixed device shape.
- Compose layout modifiers support bounded width/height constraints, and `OutlinedTextField` exposes `textStyle`, so the compact field can retain the existing Material control while centering the editable page number.

## Repair
- Landscape uses a bounded fraction of usable configuration height after IME subtraction and budgets at most four visible result rows before internal lazy scrolling.
- Portrait keeps the predecessor height behavior.
- Paging is wrapped by a full-width centering box and rendered as one intrinsic-width row.
- The page entry field is 72 dp and centers its editable text.
- Existing page validation, temporary-empty edit state, list paging animation, selected-row restoration and boundary nested-scroll behavior are retained.
- The source package excludes `screenshots`; application resources are untouched.
