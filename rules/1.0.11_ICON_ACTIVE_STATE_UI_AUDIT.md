## Demonstrated predecessor issues
The supplied 1.0.10 runtime screenshots demonstrate three concrete presentation/state defects: Local session history renders `Use as baseline` with different contained geometry from `Delete`; Settings can show the System source and a Turnip slot as active/selected at the same time after returning to System; and the Overview Encyclopedia/Analysis trailing arrows do not use the established red trailing-action treatment. The user additionally requested a complete semantic-icon pass because many unrelated sections reuse the generic information glyph.

The simultaneous active presentation is classified `BUG/CORRECTNESS`. The remaining items are `USABILITY` regressions. No Vulkan capability, driver-package, report, Database transport or storage correctness defect is inferred from the icon/shape screenshots.

## Upstream recheck
The canonical Khronos Vulkan Registry was rechecked before editing on 2026-09-08 and remains Vulkan 1.4.362 dated 2026-09-04. The release therefore keeps the existing registry/header/query/native baseline unchanged. All new icons are packaged Android vector resources and introduce no runtime network dependency.

## Repair boundary
Managed Turnip rows now derive `selected` from both the persisted active slot and current `DriverMode.TURNIP`. Settings reloads manager rows when mode changes, and the table independently suppresses stale selected presentation whenever System is active. This retains the private preferred Turnip slot without allowing two active sources to be shown simultaneously.

The local-history action row uses equal `Modifier.weight(1f)` contained icon/text buttons for `Use as baseline` and `Delete`, retaining the shared 48 dp minimum and 16x8 dp content padding. A semantic baseline/flag glyph is added.

Overview destination arrows use the same dark-red trailing icon container and Vulkan accent content used by shared chevron actions; activation remains icon-only. Page/section/action icon mappings are audited so Developer, Android, Application, Updates, Encyclopedia, Analysis, Profiles, build/library/ABI/registry/history/comparison/graph/test/save/copy/share/export concepts no longer fall back to generic Info when a dedicated symbol is available.

## Failing-before-fix evidence
`tools/verify_icon_active_state_ui_1011.py --root <immutable-1.0.10> --skip-version --skip-release-records` fails on the predecessor for the unequal baseline action, missing active-mode Turnip gate/refresh/presentation suppression, muted Overview destination arrows, generic page/section/action mappings and absent semantic vector resources. This is the release-specific failing-before-fix oracle.

## Successor evidence plan
The successor must pass the 1.0.11 source verifier, active-driver state-machine test and negative mutation suite. The negative suite deliberately reintroduces slot-only Turnip ACTIVE state, removes mode observation/presentation suppression, weakens baseline geometry, restores muted/generic icons, removes a semantic resource and verifies stale release identity is rejected. An unrelated changelog edit is the false-positive control.

Immutable 1.0.10 production/build-chain bytes are locked by `tests/golden/1.0.10_regression_contract.json`. Full retained quality, deterministic dual-ZIP reproduction, clean extraction, source/extract byte equality and clean-extract quality verification are required before final release. Android assemble/lint/unit and real-device visual reproduction are separate evidence classes and may be marked PASS only after actual successful execution.

## Android build evidence
`./gradlew :app:assembleRelease :app:lintRelease :app:testReleaseUnitTest --offline --no-daemon --stacktrace` was attempted in the release environment. Gradle 9.7.1 is not cached and the wrapper cannot resolve `services.gradle.org` (`UnknownHostException`), so Gradle/Android/Kotlin/CMake/NDK tasks did not start. `assembleRelease`, `lintRelease` and `testReleaseUnitTest` are **NOT EXECUTED**, not PASS. The user's prior successful native compilation through `compileReleaseKotlin` for 1.0.9 is not promoted as 1.0.11 build evidence.
