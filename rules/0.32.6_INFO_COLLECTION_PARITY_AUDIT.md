# VulkanScope 0.32.6 Info, collection and parity audit

- Base: VulkanScope 0.32.5.
- Manual update checking is hosted in Info beside the installed application version block; Settings no longer duplicates the action.
- While `CollectionStatus.COLLECTING` is active, System/Turnip driver switching, Turnip package selection/import, TXT export, HTML export and Database submission are unavailable.
- Activity-layer guards reject driver changes/import attempts that race with collection state changes.
- SAF export content is snapshotted before the document picker opens, so a later collection pass cannot silently replace the intended complete report while the picker is on screen.
- Installed Turnip library discovery has no arbitrary first-library fallback and reuses validated `meta.json`/canonical-path resolution.
- VulkanCapsViewer 4.12 `vulkanDeviceInfoExtensions.cpp` contains 304 named extension handlers. VulkanScope covers all 299 Android-applicable physical-device mappings; the remaining three KHR external-capability names are instance-capability paths and OHOS/QNX are non-Android platform exclusions.
- VulkanScope additionally retains the two validated post-CapsViewer-4.12 queries required by the Vulkan 1.4.360 project baseline: `VK_EXT_image_tiling_control` and `VK_EXT_cooperative_matrix_maintenance1`.
- Current Database compatibility remains the schema-v2 submission envelope with additive schema-v3 `technicalReport`, exact U64 strings, application identity and complete-collection status.

- Surface-format negative inference is now allowed only after a completed second enumeration returns `VK_SUCCESS`; partial/incomplete enumeration never turns missing pairs into unsupported claims.
- Queues UI now exposes the already-collected video decode, video encode, data graph and unknown queue-flag information instead of leaving those model fields export-only.
