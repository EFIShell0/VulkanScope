## Audit classification and observed evidence
The supplied current UI screenshots show the Properties & limits filter carousel with dark gray circular left/right arrow containers and the Queue query safety section with the plain queue/list glyph. The requested change set is classified as `USABILITY` with `REGRESSION` and `TEST-GAP` coverage because previously established 1.0.17 presentation contracts must be superseded without changing their unrelated behavior.

The update surfaces are refined from the combined ZIP-folder/download glyph to a simple downward-arrow-plus-baseline download glyph. The ZIP-folder/download artwork remains in Turnip import where ZIP-package semantics are still correct.

The shared horizontal filter carousel changes color only: red outer circular containers and white chevrons. Existing left/right geometry, animation, layout direction handling and scrolling code are retained. Vertical scroll-boundary indicators remain on their existing `ic_scroll_up` / `ic_scroll_down` path and are not modified.

Queue query safety becomes queue/list + lower-right shield. Export complete report becomes Surface + lower-right existing export arrow. Export TXT and Export HTML retain their existing primary action glyphs and add `TXT` / `HTML` badges. Explore becomes a compass.

## Current specification and retained correctness
Official Khronos registry evidence checked 2026-09-09 reports Vulkan Registry 1.4.362, published 2026-09-04. The checked-in Vulkan 1.4.362 / header 362 lock therefore remains current for this release and no floating upstream state is adopted.

Native Vulkan collection, generated registry/query data, feature/property semantics, unknown/unavailable/unsupported distinctions, report schema, Surface/display separation and complete-report gating are unchanged.

## Security, memory and performance
No permission, manifest component, native query, JNI boundary, report transport, update origin or Database origin is changed. Cleartext traffic remains disabled, backup remains disabled, the Vulkan probe service and FileProvider remain non-exported, Database upload remains explicit user initiated, and update APK download/install remains explicit.

The patch adds only local vector resources and Compose presentation logic. It does not introduce runtime image generation, network asset loading, repeated Vulkan collection during recomposition or a new long-lived resource owner. Existing probe teardown, Surface release, executor shutdown and native handle-order contracts remain retained.

## Database compatibility
VulkanScope Database 1.0.8 remains the companion consumer with schema 2 / `technicalReport` schema 3 / normalizer 16. The fixed POST and compact GET routes, privacy exclusions and 2 MiB fail-closed no-truncation ceiling are unchanged. Producer identity 1.0.19 / 1019 is the valid generic 1.0.x mapping.
