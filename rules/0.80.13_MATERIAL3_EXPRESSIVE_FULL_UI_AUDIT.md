## Demonstrated presentation defects
- USABILITY: phone-width detail dialogs force medium-length registry values into narrow right-aligned value columns, producing multi-line ragged blocks and visually unbalanced cards.
- USABILITY: detail evidence is presented as many separate rounded boxes inside another modal container, creating excessive container nesting and poor information rhythm.
- USABILITY: modal and top-level scroll-boundary indicators can occupy the same horizontal content region as technical rows.
- USABILITY: the remaining Analysis `Switch` bypasses the shared expressive wrapper.
- USABILITY: startup loading and generic empty states are materially less developed than the loaded Material 3 Expressive card hierarchy.
- USABILITY: shared action-card one-line title constraints can ellipsize important action names on phone widths.
- TEST-GAP: no release gate models the phone-width content-length transition that caused the observed detail-dialog misalignment, and no gate prevents a future return to the cramped two-column/detail-box layout.

## Current Android UI evidence
The release rechecked the current Android Developers Material 3 and dialog guidance on 2026-09-05. Material 3 Expressive is the current M3 evolution implemented by Compose Material 3. Theme color, typography and shapes are intended to form a coherent system. The current Material 3 1.5.0-alpha27 `Shapes` API includes increased large shape tiers. Android's dialog guidance distinguishes simple `AlertDialog` content from complex freeform dialogs, for which a custom `Dialog` with an explicit Material container is appropriate.

## Production correction
- The alpha27 shape scale is fully populated and shared high-level surfaces consume theme shapes.
- Complex Vulkan detail content uses a responsive custom Material dialog with a 640dp width cap and a height-aware bounded body.
- Detail evidence uses flat divided key/value rows; ordinary capability pages retain tonal rows.
- Key/value and update metadata choose stacked versus two-column layout from actual available width, text scaling and content length, and no longer right-align multi-line values.
- Shared scroll indicators become one compact rail and top-level/detail content reserves a non-overlap lane.
- Format/Extension list rows use the common capability-item surface and Details becomes a morphing expressive TextButton with the existing explicit Button role.
- Analysis routes its unchanged toggle through `ExpressiveSwitch`.
- Startup loading and empty states adopt the shared surface/icon/text hierarchy and startup progress remains indeterminate.
- Action cards permit bounded title/subtitle wrapping.
