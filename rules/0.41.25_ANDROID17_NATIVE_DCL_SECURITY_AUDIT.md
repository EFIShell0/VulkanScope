# VulkanScope 0.41.25 Android 17 native dynamic-code security audit

## Scope

This release re-audits VulkanScope 0.41.24 against `PROJECT_RULES.md`, the Vulkan 1.4.360 registry baseline and Android 17/API 37 native dynamic-code requirements. The review covers canonical Vulkan naming and evidence states, complete-report retention, Surface/WSI handling, isolated-probe ownership, native/JNI lifecycle, update and Database paths, Turnip package loading, bounds, UI/export behavior and release hygiene.

## Correction

The Turnip/AdrenoTools import path dynamically loads user-selected native code from VulkanScope private storage. Imported `.so` files were structurally validated and privately confined but remained writable after extraction. 0.41.25 makes every native `.so` read-only immediately after opening its destination file and before writing package bytes, verifies the bounded native-library set is canonically confined/readable/non-writable before atomic installation, and fail-closed verifies/hardens the bounded whole installed native-library set before every loader resolution, including dependencies when the selected library was already read-only.

The same audit found that ZIP expansion and validation could run synchronously from the ActivityResult callback on the UI thread. 0.41.25 moves the full bounded import transaction to `Dispatchers.IO`, observes coroutine cancellation inside entry/data loops, fsyncs native libraries and `meta.json` before installation, cleans temporary state on failure/cancellation, and rejects concurrent import attempts. Main-thread work is limited to user feedback and the final driver-mode transition.

The Vulkan collector, registry catalog, report schemas and evidence semantics are intentionally unchanged. No new unmatched JNI string, Android native-window, Vulkan instance/surface/device, file-descriptor or isolated-worker lifetime was identified by the static ownership review.

Dependency freshness was also rechecked against the AndroidX 2026-08-26 release table and current Kotlin release guidance. The active Material 3 Expressive dependency is updated from 1.5.0-alpha26 to 1.5.0-alpha27; Compose UI, Foundation and Animation remain on stable 1.12.0. The Compose compiler Gradle plugin is updated from Kotlin 2.3.21 to current stable Kotlin 2.4.10 while retaining AGP 9 built-in Kotlin. OkHttp is updated from 5.2.0 to current stable 5.5.0 for current transport fixes while keeping VulkanScope's custom system-DNS and endpoint policy unchanged; new ECH/alternate-DNS features are not enabled. The alpha27 API changes are outside VulkanScope's used TimePicker/menu surface, so no application API migration is required by this update.

## Verification policy

The release verifier gates the read-only-before-write extraction pattern, pre-install native-library verification, legacy fail-closed hardening and all prior release invariants. The final source ZIP must be independently re-extracted and checked for verifier success, JSON/XML parsing, Python syntax, `files.txt` parity, safe ZIP paths, duplicate entries, symlinks and executable wrapper metadata. A Gradle build is claimed only when Android/Kotlin/CMake tasks actually complete.
