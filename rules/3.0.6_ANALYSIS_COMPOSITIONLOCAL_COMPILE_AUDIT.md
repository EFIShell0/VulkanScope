# VulkanScope 3.0.6 Analysis CompositionLocal Compile Audit

## Scope

VulkanScope 3.0.6 is a compile-regression repair over immutable VulkanScope 3.0.5 (`5a98bc562757d74ca438caabf94954c09428a17407ff0279c164dc39d54dc78c`, 821 files). Production runtime-source changes are restricted to `MainActivity.kt`; `app/build.gradle.kts` changes release identity only. `AdvancedAnalysis.kt`, `VulkanDependencyGraph.kt`, manifest, native/JNI Vulkan collection, Vulkan registry/generated data, report/export schemas, permissions, ABI targets and dependency versions remain predecessor-equivalent.

## Observed regression

The supplied release build completes C/C++ compilation for arm64-v8a, armeabi-v7a and x86_64, then fails `:app:compileReleaseKotlin`. Kotlin reports that `analysisWorkspaceItems` invokes a composable function even though the `LazyListScope` builder is not composable, and identifies the `LocalValidatedNetwork.current` read inside the Database branch as the offending composable invocation.

Official Android Compose documentation was rechecked on 2026-09-29 before patching. `LazyColumn` uses a non-composable `LazyListScope.()` DSL to describe items, while each `item` content lambda is composable. The validated-network CompositionLocal therefore has to be read from an actual composable scope rather than directly from the lazy-list DSL builder.

## Repair

`AnalysisPage` now reads `LocalValidatedNetwork.current` once in its existing `@Composable` scope and passes the resulting Boolean to `analysisWorkspaceItems`. The lazy builder no longer reads the CompositionLocal. Database list and Report ID controls consume the same Boolean as before, so request gating, explicit-action behavior, endpoints, response bounds and comparison semantics are unchanged.

## Evidence boundary

`tools/verify_release_3006.py` enforces release identity, composable-scope network acquisition, ordinary Boolean threading, absence of a CompositionLocal read inside the lazy builder and preservation of the 3.0.5 UI/workflow anchors. `tools/test_release_3006_state_machine.py` models network gating across both Database lookup modes. `tools/test_release_3006_negative_mutations.py` reintroduces the observed compile defect and a forced-network bypass and requires verifier failure while a documentation-only mutation remains accepted. `tools/verify_release_3006_regression.py` requires every production file except `MainActivity.kt` to remain byte-equivalent to 3.0.5 and requires `MainActivity.kt` to normalize exactly back to the immutable predecessor using only the documented repair. Android compilation and device replay remain separate evidence classes.
